기술적설명	
1. 스마트 팜 센서 구현
수행과제
스마트 팜(Smart Parm)의 센서들을 구현해야 한다. 센서는 다음과 같은 항목들을 가지고 있다.
온도: Temperature
조도: Illuminance or Light Intensity
습도: Humidity
각각의 센서 값은 다음 범위 안에서 랜덤으로 값을 생성해 낸다.
온도: 20~30
조도: 5000~10000
습도: 40~70
센서 값을 출력하는 클래스를 ParmSensor 클래스로 생성한다. 여기에는
센서의 고유이름을 속성으로 포함한다.
온도, 조도, 습도 등을 속성으로 포함한다.  
SetData()를 호출하면 랜덤으로 제한된 범위안의 값을 생성해서 온도, 조도, 습도의 속성에 채워 넣는다.
GetData()를 호출하면 온도, 조도, 습도의 값을 돌려준다.
ParmSensor 클래스를 5개의 인스턴스로 만들어 각각 Parm-1~5까지 고유이름을 설정해 준다.
멀티 쓰레드로 Parm1~5의 SetData(), GetData()를 10초 단위로 호출해 주고 그 결과를 화면에 다음과 같이 출력해 준다.
2000-08-01 14:30:30 Parm1 — temp 00, light 000, humi 00
모든 센서의 값이 골고루 다 출력되는지 확인한다.

좋아요! 아래는 스마트 팜 센서 모니터링 프로그램의 전체 실행 흐름을 **순서대로**, 그리고 **자세히** 설명한 것입니다. 이 코드는 `main()` 함수 안에 모든 실행 로직이 들어 있고, `if __name__ == '__main__':`을 통해 직접 실행될 때만 작동합니다.

📦 ParmSensor 클래스                      # 스마트팜 센서 객체 정의
├── __init__(name)                      # 센서 이름 및 초기값 설정
├── SetData()                           # 온도, 조도, 습도 무작위 생성
└── GetData()                           # 센서 데이터 반환 (온도, 조도, 습도)

📦 sensor_worker(sensor, stop_event)     # 센서 쓰레드 함수
├── while not stop_event.is_set():      # 종료 이벤트가 설정되지 않으면 반복
│   ├── sensor.SetData()                # 센서 데이터 생성
│   ├── sensor.GetData()                # 센서 데이터 가져오기
│   ├── timestamp = datetime.now()      # 현재 시간 포맷팅
│   ├── if humi > 90:                   # 습도 90% 초과 시 빨간색 출력
│   └── for _ in range(10):             # 10초 대기 (1초씩 나눠서 체크)
│       └── time.sleep(1)               # 1초 대기
└── 종료 이벤트 감지 시 루프 탈출

📦 main()                                # 프로그램 실행 함수
├── stop_event = threading.Event()      # 종료 이벤트 생성
├── sensors = [ParmSensor(...)]         # 센서 5개 생성 (Parm-1 ~ Parm-5)
├── for sensor in sensors:              # 각 센서에 대해 쓰레드 생성 및 시작
│   ├── thread = threading.Thread(...)  # 쓰레드 객체 생성
│   ├── thread.start()                  # 쓰레드 시작
│   └── threads.append(thread)          # 쓰레드 리스트에 추가
├── 사용자 입력 루프 시작
│   └── if input == 'q':                # 'q' 입력 시 종료 이벤트 설정
├── for thread in threads:              # 모든 쓰레드 종료 대기
│   └── thread.join()                   # 쓰레드 종료까지 대기
└── 종료 메시지 출력

📦 if __name__ == '__main__':           # 프로그램 시작점
└── main()                              # main 함수 호출

## 🧭 실행 순서 설명

### 1️⃣ 프로그램 시작

```python
if __name__ == '__main__':
    main()
```

- 이 줄은 Python에서 해당 파일이 직접 실행될 때만 `main()` 함수를 호출하도록 합니다.
- 다른 모듈에서 import될 경우 `main()`은 실행되지 않습니다.

---

### 2️⃣ main() 함수 진입

```python
def main():
```

- 프로그램의 핵심 로직이 이 함수 안에 들어 있습니다.

---

### 3️⃣ 종료 이벤트 생성

```python
stop_event = threading.Event()
```

- `stop_event`는 쓰레드에게 "이제 그만 종료하라"는 신호를 보내는 용도로 사용됩니다.
- 나중에 `q` 키를 누르면 이 이벤트가 활성화되어 모든 센서 쓰레드가 종료됩니다.

---

### 4️⃣ 센서 객체 생성

```python
sensors = [ParmSensor(f"Parm-{i}") for i in range(1, 6)]
```

- `ParmSensor` 클래스의 인스턴스를 5개 생성합니다.
- 각각의 센서는 `"Parm-1"`부터 `"Parm-5"`까지 고유 이름을 가집니다.

---

### 5️⃣ 센서 쓰레드 생성 및 시작

```python
for sensor in sensors:
    thread = threading.Thread(target=sensor_worker, args=(sensor, stop_event))
    thread.start()
    threads.append(thread)
```

- 각 센서마다 하나의 쓰레드를 생성합니다.
- 쓰레드는 `sensor_worker()` 함수를 실행하며, 센서 객체와 종료 이벤트를 인자로 받습니다.
- 쓰레드는 시작되며, `threads` 리스트에 저장됩니다.

---

### 6️⃣ 사용자 안내 메시지 출력

```python
print("센서 모니터링 중... 종료하려면 'q'를 입력하세요.")
```

- 사용자에게 `q` 키를 입력하면 종료된다는 메시지를 보여줍니다.

---

### 7️⃣ 사용자 입력 대기 루프

```python
while True:
    user_input = input()
    if user_input.strip().lower() == 'q':
        print("종료 중...")
        stop_event.set()
        break
```

- 사용자가 `q`를 입력할 때까지 계속 대기합니다.
- `q`가 입력되면 `stop_event.set()`을 호출하여 모든 쓰레드에 종료 신호를 보냅니다.
- 이후 루프를 탈출합니다.

---

### 8️⃣ 쓰레드 종료 대기

```python
for thread in threads:
    thread.join()
```

- 모든 센서 쓰레드가 종료될 때까지 기다립니다.
- `join()`은 해당 쓰레드가 완전히 종료될 때까지 메인 쓰레드를 블로킹합니다.

---

### 9️⃣ 종료 메시지 출력

```python
print("모든 센서 쓰레드가 종료되었습니다.")
```

- 모든 쓰레드가 정상적으로 종료되었음을 사용자에게 알립니다.

## 🔁 쓰레드 내부 동작 (`sensor_worker` 함수)

각 쓰레드는 다음을 반복합니다:

1. `SetData()` 호출 → 센서 값(온도, 조도, 습도)을 랜덤으로 생성
2. `GetData()` 호출 → 센서 값을 가져옴
3. 현재 시간과 센서 이름, 센서 값을 출력
   - 습도가 90% 초과하면 빨간색으로 강조
4. `time.sleep(10)` → 10초 대기 후 다시 반복

이 루프는 `stop_event`가 설정될 때까지 계속 반복됩니다.

네, 아주 날카로운 질문이에요! 👍  
지금 사용한 `threading.Event()` 방식과 예전에 `queue`를 사용해서 쓰레드를 멈추던 방식은 **비슷한 목적을 갖고 있지만, 동작 방식은 다릅니다**. 둘 다 쓰레드 간의 **통신과 제어**를 위한 도구지만, 사용하는 방식과 쓰레드가 멈추는 구조는 조금 달라요.

---

## 🔁 `threading.Event()` 방식

- **역할**: 쓰레드에게 "이제 멈춰라"는 **신호(flag)**를 전달
- **특징**:
  - `stop_event.set()`으로 종료 신호를 보냄
  - 쓰레드는 `stop_event.is_set()`을 주기적으로 확인
  - **데이터 전달은 없음**, 오직 상태(켜짐/꺼짐)만 전달

```python
stop_event = threading.Event()

while not stop_event.is_set():
    # 작업 수행
    time.sleep(1)
```

---

## 📦 `queue.Queue()` 방식

- **역할**: 쓰레드 간에 **데이터를 전달**하거나 **작업을 분배**
- **종료 방식**:
  - 보통 `None`이나 `"STOP"` 같은 **특수 메시지**를 큐에 넣어 종료 신호로 사용
  - 쓰레드는 큐에서 메시지를 꺼내서 `"STOP"`이면 종료

```python
from queue import Queue

q = Queue()

def worker():
    while True:
        task = q.get()
        if task == "STOP":
            break
        # 작업 수행
        q.task_done()
```

---

## 🔍 비교 요약

| 항목 | `threading.Event()` | `queue.Queue()` |
|------|----------------------|------------------|
| 목적 | 상태 신호 전달 | 데이터/작업 전달 |
| 종료 방식 | `is_set()` 확인 | `"STOP"` 메시지 수신 |
| 쓰레드 수 | 여러 쓰레드에 동시에 적용 가능 | 쓰레드별 메시지 필요 |
| 코드 구조 | 간단하고 직관적 | 유연하지만 복잡할 수 있음 |
| CPU 효율 | 매우 효율적 | 효율적 (단, 큐 polling 시 주의) |

## 🧠 결론

- 지금처럼 **센서 쓰레드가 주기적으로 작업하고 종료 신호만 받는 구조**라면 `threading.Event()`가 훨씬 간단하고 효율적입니다.
- 반면, **작업을 분배하거나 데이터 흐름을 제어해야 하는 경우**에는 `queue.Queue()`가 더 적합합니다.

혹시 센서 데이터를 저장하거나 분석하는 작업을 쓰레드로 분리하고 싶다면, `Queue` 기반 구조도 고려해볼 수 있어요. 원하시면 예제도 보여드릴게요!
