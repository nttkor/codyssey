맞습니다! **ZipCrypto**에서 암호화된 **Zip 파일의 암호**는, 말하자면 `key1`, `key2`, `key3`라는 **세 개의 키**에 영향을 주며, 암호화와 복호화 과정에서 중요한 역할을 합니다. 암호는 **키 스트림을 생성하는 데 사용**되며, 이는 파일의 데이터를 암호화하고 복호화하는 데 필요합니다.

좀 더 자세히 설명드리자면, **Zip 파일 암호화**에 사용된 비밀번호는 **키스트림 생성**의 초기값으로 사용됩니다. 이 키스트림은 **데이터 암호화**와 **복호화**에서 동일하게 사용됩니다.

### ZipCrypto에서 암호(비밀번호)의 사용

1. **비밀번호 입력**:
   Zip 파일을 열 때 사용자가 비밀번호를 입력하게 되면, 이 비밀번호는 **초기화 벡터**로 사용됩니다. 즉, 이 비밀번호가 **암호화 키의 기초**가 됩니다.

2. **초기화**:
   ZipCrypto에서는 세 개의 키(`key1`, `key2`, `key3`)가 각각 `0x12345678`, `0x23456789`, `0x34567890`이라는 기본값으로 설정됩니다. 이 세 키는 **비밀번호에 따라 업데이트**됩니다. 비밀번호를 바탕으로 세 키 값을 수정하고, 그 후 각 키 값에서 추출된 값들이 **암호화된 데이터와 XOR 연산**을 통해 키스트림을 생성하는 데 사용됩니다.

3. **키스트림 생성**:
   비밀번호를 **`password.encode()`** (즉, 바이트로 변환)한 후, 각 비밀번호 바이트마다 \*\*키값(`key1`, `key2`, `key3`)\*\*을 업데이트합니다. 이 값들을 이용해 암호화 및 복호화에서 사용할 **키스트림**을 생성합니다.

4. **키스트림을 이용한 암호화**:
   이 키스트림은 **암호화된 데이터를 XOR**하는 데 사용됩니다. 암호화할 데이터는 키스트림의 바이트들과 XOR 연산을 반복하면서 암호화됩니다. 암호화된 Zip 파일은 이렇게 암호화된 데이터를 저장하게 됩니다.

### 비밀번호와 키스트림 업데이트 과정

ZipCrypto 암호화에서 **비밀번호**는 세 개의 키(`key1`, `key2`, `key3`)를 **업데이트**하는 데 사용되며, 이를 통해 **키스트림을 생성**합니다. 이 과정은 반복적으로 진행됩니다. 예를 들어:

* 비밀번호의 첫 번째 바이트가 `key1`, `key2`, `key3`에 영향을 미쳐 키값을 갱신하고,
* 그 후 그 값들을 바탕으로 새로운 키스트림을 생성합니다.

#### 간단한 예시:

1. 비밀번호 `password`가 주어졌다고 가정해봅시다.

2. 비밀번호의 각 바이트는 키값을 변경하는 데 사용됩니다:

   * `key1`, `key2`, `key3`는 기본값으로 설정되며,
   * `password`의 첫 번째 바이트에 따라 이 키들이 업데이트됩니다.

3. 이렇게 생성된 새로운 키값들은 **키스트림을 생성**하는 데 사용됩니다.

4. 이 키스트림은 암호화할 데이터에 **XOR 연산**을 통해 적용되며, 암호화된 데이터를 만들어 냅니다.

### ZipCrypto의 암호화 및 복호화 코드 분석

```python
import zipfile

# 초기화 벡터 (key1, key2, key3)
keys = [0x12345678, 0x23456789, 0x34567890]  # 초기화된 키들

# 비밀번호를 바이트로 변환
password = 'password'
password_bytes = password.encode()  # 비밀번호를 바이트로 변환

# 비밀번호에 의해 keys 값 갱신
for i in range(len(password_bytes)):
    key = password_bytes[i]
    # key1, key2, key3 업데이트
    keys[0] = (keys[0] + (key >> 8)) & 0xFFFFFFFF
    keys[1] = (keys[1] + (key & 0xFF)) & 0xFFFFFFFF
    keys[2] = (keys[2] + key) & 0xFFFFFFFF

# 파일 열기
with zipfile.ZipFile('encrypted.zip') as zf:
    with zf.open('file.txt') as f:
        encrypted_data = f.read()

        # 복호화 처리 (암호화된 데이터를 XOR 연산으로 복호화)
        decrypted_data = bytearray()

        for byte in encrypted_data:
            # 키스트림에서 가져온 값으로 XOR 연산 수행
            keystream_byte = (keys[0] >> 8) ^ (keys[1] & 0xFF) ^ (keys[2] & 0xFF)
            decrypted_data.append(byte ^ keystream_byte)

        # 복호화된 데이터 출력
        print(decrypted_data.decode())
```

### 이 코드에서의 흐름:

1. \*\*비밀번호 `password`\*\*는 `password.encode()`로 바이트 형식으로 변환됩니다.
2. 각 **비밀번호 바이트**는 `key1`, `key2`, `key3`를 업데이트하는 데 사용됩니다.
3. 이 **업데이트된 키 값들**은 **키스트림**을 생성하는 데 사용됩니다.
4. 암호화된 파일을 열 때, 이 **키스트림**을 이용해 XOR 연산을 진행하여 원본 데이터를 복원합니다.

### 결론

* **ZipCrypto 암호화**에서 비밀번호는 **초기화 벡터**로 사용되며, 그에 따라 세 개의 키 (`key1`, `key2`, `key3`)를 업데이트하고, 이 키들은 **키스트림을 생성**하는 데 사용됩니다.
* 이 키스트림은 암호화 및 복호화 과정에서 동일하게 사용되며, **암호화된 데이터를 XOR 연산**을 통해 복원할 수 있습니다.


맞아요, ZipCrypto의 복호화를 이해하려면 암호화 과정부터 공부하는 게 좋습니다. ZipCrypto 암호화는 상대적으로 간단한 **스트림 암호화 방식**을 기반으로 하고 있어서, 그 원리를 이해하면 복호화 과정도 자연스럽게 따라올 수 있습니다.

### ZipCrypto 암호화 과정 간단히 설명하기

ZipCrypto는 **대칭 키 암호화** 방식을 사용하며, 암호화된 파일을 압축 해제할 때 해당 키로 복호화하는 방식입니다. 암호화는 원본 데이터를 XOR 연산을 통해 암호화된 텍스트로 변환하며, 이를 위해 **키스트림**을 생성하는 알고리즘을 사용합니다.

### 1. **암호화 과정 개요**

ZipCrypto의 암호화는 다음과 같은 단계로 이루어집니다:

1. **키스트림(Key Stream) 생성**

   * ZipCrypto는 암호화할 데이터를 **3개의 키**(`keys[0]`, `keys[1]`, `keys[2]`)를 기반으로 XOR 연산을 사용해 키스트림을 생성합니다.
   * 이 키스트림은 암호화할 각 바이트마다 XOR 연산을 통해 적용됩니다.

2. **XOR 연산을 통한 암호화**

   * 원본 데이터를 키스트림과 XOR 연산을 수행하여 암호화된 데이터를 만듭니다.
   * 이때 원본 데이터의 각 바이트에 대해 **키스트림의 각 바이트**와 XOR 연산을 진행합니다.

3. **암호화된 결과 저장**

   * 최종적으로 암호화된 데이터는 **압축 파일**에 저장됩니다.

### 2. **암호화 과정 상세 분석**

암호화 과정에서 ZipCrypto는 **세 개의 키**를 사용하여 키스트림을 생성합니다. 이 키들은 초기값으로 주어진 `0x12345678`, `0x23456789`, `0x34567890`에서 시작합니다. 그 후 이 키들은 반복적으로 업데이트되어 **새로운 키스트림**을 생성합니다. 키스트림은 매번 다른 바이트 값을 생성하므로 암호화된 데이터가 **보안적으로 안전**하게 처리됩니다.

#### 암호화 알고리즘의 간단한 흐름:

1. 초기화:

   * `key1`, `key2`, `key3`는 각각 `0x12345678`, `0x23456789`, `0x34567890`으로 설정됩니다.

2. 키스트림 생성:

   * 각 키는 복잡한 알고리즘을 통해 **업데이트**되며, 키스트림의 새로운 바이트를 생성합니다.
   * `keys[0]`, `keys[1]`, `keys[2]` 값은 **매번 변화**합니다. 이 변화는 키스트림을 예측 불가능하게 만들어, 암호화된 데이터가 안전하게 유지되도록 합니다.

3. XOR 연산:

   * 암호화할 원본 데이터에 대해 **각각 생성된 키스트림 바이트**와 XOR 연산을 통해 암호화된 데이터를 생성합니다.

4. 최종 암호화된 데이터는 **압축 파일**에 저장됩니다.

### 3. **ZipCrypto 암호화 코드 흐름**

```python
import zipfile

# 암호화된 Zip 파일을 연다
with zipfile.ZipFile('encrypted.zip') as zf:
    password = 'password'  # 암호화에 사용된 비밀번호

    # 키스트림 생성 (암호화/복호화에 동일한 키스트림이 사용됨)
    password_bytes = password.encode()  # 비밀번호를 바이트로 변환
    keys = [0x12345678, 0x23456789, 0x34567890]  # 초기화 벡터

    # 비밀번호에 따라 키스트림을 갱신
    for i in range(len(password_bytes)):
        key = password_bytes[i]
        # 키값 업데이트 (키스트림 생성)
        keys[0] = (keys[0] + (key >> 8)) & 0xFFFFFFFF
        keys[1] = (keys[1] + (key & 0xFF)) & 0xFFFFFFFF
        keys[2] = (keys[2] + key) & 0xFFFFFFFF

    # 실제 암호화된 데이터를 키스트림과 XOR하여 압축 해제
    with zf.open('somefile.txt') as f:
        encrypted_data = f.read()
        decrypted_data = bytearray()

        for byte in encrypted_data:
            # 키스트림을 이용해 데이터를 복호화
            keystream_byte = (keys[0] >> 8) ^ (keys[1] & 0xFF) ^ (keys[2] & 0xFF)
            decrypted_data.append(byte ^ keystream_byte)

        # 복호화된 데이터를 사용
        print(decrypted_data.decode())
```

### 4. **복호화 과정**

ZipCrypto의 복호화 과정은 암호화 과정과 거의 동일합니다. 복호화할 때에도 **같은 키스트림**을 사용해야 하므로, 암호화할 때 사용했던 **비밀번호**를 알고 있으면 동일한 키스트림을 생성하여 원본 데이터를 복원할 수 있습니다.

* **암호화된 데이터와 XOR 연산**을 반복하면서 원본 데이터를 복원합니다.
* 복호화 과정에서 중요한 점은 **암호화할 때 사용된 키스트림과 동일한 키스트림을 복호화에도 사용**해야 한다는 것입니다.

### 5. **ZipCrypto의 보안성**

ZipCrypto는 **보안성이 낮은 암호화 방식**으로 알려져 있습니다. 특히 암호화의 **키 스트림**이 예측 가능한 방식으로 생성되기 때문에, 강력한 보안이 필요한 환경에서는 **AES-256**과 같은 **더 강력한 암호화 알고리즘**을 사용하는 것이 좋습니다.

### 결론

ZipCrypto 암호화를 이해하려면 **암호화**와 **복호화** 과정에서 사용되는 **키스트림 생성 및 XOR 연산**을 정확히 이해하는 것이 중요합니다. 암호화는 단순한 XOR 연산을 이용하지만, **3개의 키**와 **키스트림 생성 방식**을 잘 이해해야 보안적인 측면에서 그 원리를 완전히 파악할 수 있습니다.

복호화 과정은 암호화에서 사용된 **동일한 키스트림**을 이용해 XOR 연산을 반복하며 원본 데이터를 복원하는 방식입니다.


\*\*키스트림(Key Stream)\*\*은 암호화에서 중요한 개념으로, **암호화/복호화에 사용되는 가변적인 키**입니다. 이 키스트림은 **대개 암호화된 데이터와 XOR 연산을 수행**하여 데이터를 보호하는 데 사용됩니다. 키스트림은 대개 **난수처럼 보이는 값**이지만, 실제로는 특정 알고리즘에 의해 **예측할 수 없는** 순서로 생성됩니다.

### 1. **키스트림의 정의**

키스트림은 **암호화 알고리즘**에서 사용되는 **암호화 키**의 흐름을 의미합니다. 보통 **대칭 키 암호화**에서 **암호화와 복호화**를 할 때 **같은 키**가 사용되는데, 이 키스트림을 사용하여 데이터를 **XOR 연산**합니다. 이 과정은 **스트림 암호**(Stream Cipher)라는 암호화 기법에서 핵심적인 부분입니다.

### 2. **스트림 암호에서의 키스트림**

스트림 암호에서 키스트림은 **무작위의 숫자**로 이루어져 있는 **가변적인 키**로, 이 키를 사용하여 데이터와 연산을 하게 됩니다. 스트림 암호는 **블록 암호**(Block Cipher)와 달리 **문자 단위**로 데이터를 암호화하고, **암호화된 데이터**는 원래의 데이터와 동일한 길이를 가집니다.

### 3. **키스트림 생성**

키스트림은 **일종의 난수 생성기**로 생성되며, 대개 특정한 **시드 값**을 기반으로 합니다. 시드 값은 주로 **비밀 키**나 **암호화할 메시지**와 관련된 정보를 포함합니다. 시드 값이 바뀌면 생성되는 키스트림도 달라지므로, 암호화가 **매번 다르게** 수행됩니다.

예를 들어, **RC4**와 같은 스트림 암호에서는 \*\*초기화 벡터(IV)\*\*와 **비밀 키**를 이용해 키스트림을 생성합니다.

### 4. **키스트림의 역할**

암호화된 데이터를 **복호화**하려면 암호화할 때 사용한 **키스트림**과 동일한 키스트림을 사용해야 합니다. 복호화 과정에서 **XOR 연산**을 다시 한 번 수행하면 원본 데이터가 복원됩니다.

즉, **키스트림**은 암호화 과정과 복호화 과정에서 동일하게 사용되어야 합니다. 이 과정에서 중요한 점은 키스트림이 **예측 불가능하고, 중복되지 않아야** 한다는 것입니다.

### 5. **XOR 연산과 키스트림**

XOR 연산은 두 값이 다르면 `1`, 같으면 `0`을 반환하는 논리 연산입니다. 이 특성 덕분에 **XOR 연산**은 **대칭성**을 가집니다. 즉, 암호화와 복호화에 같은 키스트림을 사용하면 원본 데이터를 복원할 수 있습니다.

#### 예시: XOR 연산

* **암호화**:

  * 원본 데이터 (`plaintext`)와 키스트림 (`keystream`)을 XOR 연산합니다.
  * `ciphertext = plaintext ^ keystream`
* **복호화**:

  * 암호화된 데이터 (`ciphertext`)와 동일한 키스트림 (`keystream`)을 XOR 연산합니다.
  * `plaintext = ciphertext ^ keystream`

XOR 연산이 **대칭적**이므로 암호화와 복호화에 동일한 키스트림을 사용하여 원본 데이터를 복원할 수 있습니다.

### 6. **ZipCrypto에서의 키스트림**

ZipCrypto 암호화에서, 암호화된 데이터를 복호화하기 위해서는 **키스트림을 생성**하고, 이를 암호화된 데이터와 **XOR 연산**해야 합니다. 이때 키스트림은 **3개의 키**로부터 생성되며, **암호화 및 복호화** 과정에서 각 키는 **각기 다른 방식으로 업데이트**됩니다.

ZipCrypto의 경우, **세 개의 키**(`keys[0]`, `keys[1]`, `keys[2]`)가 각각 다르게 업데이트되어, 이들을 이용해 생성된 **키스트림**이 암호화된 데이터를 **복호화**하는 데 사용됩니다.

### 7. **키스트림의 특징**

* **예측 불가능성**: 키스트림은 예측할 수 없는 방식으로 생성되어야 합니다. 예를 들어, 난수 생성기나 알고리즘을 통해 생성된 키스트림은 외부에서 예측하기 어려워야 합니다.
* **고유성**: 각 암호화된 메시지에 대해 고유한 키스트림을 사용하는 것이 이상적입니다. 동일한 키스트림을 두 번 사용하면 암호가 취약해질 수 있습니다.
* **같은 키스트림을 사용한 암호화/복호화**: 암호화된 데이터를 복호화하려면 암호화에 사용된 것과 **동일한 키스트림**을 사용해야 합니다.

### 8. **결론**

**키스트림**은 스트림 암호에서 사용되는 **변동하는 키 값**이며, 암호화 및 복호화에서 중요한 역할을 합니다. 이를 통해 **XOR 연산**을 사용하여 원본 데이터를 암호화하거나 복호화할 수 있습니다. ZipCrypto와 같은 알고리즘에서 키스트림은 **여러 키**를 조합하여 생성되며, **데이터의 보안성**을 강화하는 데 중요한 역할을 합니다.


ZIP 파일에서 **ZipCrypto 암호화 방식**을 사용할 때, **3개의 키**(`keys[0]`, `keys[1]`, `keys[2]`)를 사용하는 이유는 이 방식이 **3단계의 키 업데이트 및 흐름 생성**을 기반으로 한 복잡한 알고리즘이기 때문입니다. 이 3개의 키는 단순히 하나의 키가 아닌, 서로 연관된 상태에서 각기 다른 역할을 하며 **암호화 및 복호화** 과정을 거치게 됩니다.

이해를 돕기 위해 **ZipCrypto 암호화 방식**의 핵심 구조와 3개의 키가 어떻게 동작하는지 자세히 설명하겠습니다.

### 1. **ZipCrypto 암호화 알고리즘의 기본 흐름**

ZipCrypto는 **3개의 키**를 사용하여 암호화 및 복호화를 수행하는데, 이 키들은 **순차적으로 업데이트**됩니다. 각 키는 ZIP 헤더와 파일 데이터의 **바이트 단위**로 작업을 합니다.

* **`keys[0]`**: 가장 중요한 키로, 암호화 및 복호화의 초기 상태를 설정합니다.
* **`keys[1]`**: 두 번째 키로, 키 업데이트 과정에서 중요한 역할을 하며 키의 비트수와 관계된 작업을 수행합니다.
* **`keys[2]`**: 세 번째 키로, 다른 두 키와 함께 최종 복호화된 바이트를 결정합니다.

### 2. **3개의 키를 사용하는 이유**

각각의 키는 다른 역할을 수행하며, 복잡한 **키 업데이트** 및 **바이트 XOR 연산** 과정을 통해 암호화된 데이터를 복호화할 수 있도록 합니다. 이를 통해 보안을 강화하고, **단일 키** 방식에 비해 훨씬 더 높은 보안성을 유지할 수 있습니다.

#### 2.1. **키 초기화 및 업데이트**

```python
self.keys[0] = self.crc32_update(self.keys[0], byte)
self.keys[1] = ((self.keys[1] + (self.keys[0] & 0xFF)) * 134775813 + 1) & 0xFFFFFFFF
self.keys[2] = self.crc32_update(self.keys[2], (self.keys[1] >> 24) & 0xFF)
```

* \*\*`keys[0]`\*\*는 `password`의 **각 바이트**에 대해 CRC32 연산을 통해 초기화되거나 업데이트됩니다.
* \*\*`keys[1]`\*\*은 `keys[0]`의 **하위 8비트** 값을 이용하여 선형 변환을 진행한 후, **134775813**과 같은 큰 수를 곱해서 업데이트됩니다. 이 값은 **고정된 상수**입니다.
* \*\*`keys[2]`\*\*는 \*\*`keys[1]`\*\*의 상위 8비트를 사용하여 CRC32 연산을 통해 업데이트됩니다.

#### 2.2. **암호화 및 복호화 과정**

이 세 키는 데이터를 복호화하기 위해 서로 다른 방식으로 결합되어 사용됩니다. 복호화 과정에서 중요한 점은 **키의 흐름을 계속 업데이트**한다는 것입니다. 즉, **한 번의 암호화**가 아니라 **각각의 바이트마다 키가 지속적으로 변하며 적용**됩니다.

### 3. **왜 3개의 키를 사용해야 하는가?**

1. **보안 강화**:

   * 단일 키를 사용할 경우, 키에 대한 예측이 가능해집니다. 그러나 3개의 키를 사용하면 암호화가 더 복잡해져서 공격자가 키를 추측하기 어렵습니다.
   * 또한, 서로 다른 방식으로 업데이트되는 3개의 키를 사용하면 **암호화의 비선형성**을 보장할 수 있습니다. 이는 암호 해독을 더 어렵게 만듭니다.

2. **성능 최적화**:

   * 각 키는 독립적으로 업데이트되지만 서로 연관된 방식으로 작동하므로, 빠르고 효율적인 암호화 및 복호화가 가능해집니다. CRC32나 선형 변환을 통한 업데이트는 계산이 간단하고 빠르기 때문에 성능에 유리합니다.

3. **상호 보완적인 역할**:

   * `keys[0]`, `keys[1]`, `keys[2]`는 서로 **다른 비트 길이와 연산 방식**을 통해 작동합니다. 이들은 **각기 다른 방식으로 키를 변형**시키고, 복호화된 데이터를 더 복잡하게 만듭니다.

   예를 들어, `keys[0]`은 CRC32 연산을 사용하여 각 바이트에 대해 **일관된 해시값**을 생성하고, `keys[1]`은 **선형 변환**을 통해 다음 키의 값에 영향을 미치며, `keys[2]`는 **상위 바이트**를 기준으로 다시 CRC32 연산을 진행하여 **다양한 값을 조합**합니다.

### 4. **암호화/복호화에서의 동작 예시**

암호화/복호화 과정에서 실제로 어떻게 이 세 키가 사용되는지 살펴보면, 한 바이트를 복호화할 때 아래와 같은 흐름이 발생합니다:

* **키 스트림 생성**:
  각 키는 특정한 방식으로 업데이트되며, 그 결과로 나온 값을 **키 스트림**으로 사용합니다.
* **XOR 연산**:
  암호화된 데이터 바이트와 키 스트림을 **XOR 연산**하여 복호화된 데이터를 얻습니다.

#### 4.1. 복호화 예시:

```python
temp = (self.keys[2] & 0xFFFF) | 2
keystream = ((temp * (temp ^ 1)) >> 8) & 0xFF
plain = enc_byte ^ keystream
self.update_keys(plain)
```

* \*\*`keystream`\*\*은 `keys[2]`에 기반하여 생성됩니다.
* \*\*`plain`\*\*은 XOR 연산을 통해 암호화된 바이트(`enc_byte`)를 복호화하여 얻은 값입니다.
* \*\*`self.update_keys(plain)`\*\*은 복호화된 바이트를 기반으로 다시 키를 업데이트합니다.

### 키 업데이트 과정

주어진 코드에서 `update_keys`와 `init_keys` 함수는 **비밀번호**를 이용해 **세 개의 키**(`keys[0]`, `keys[1]`, `keys[2]`)를 **업데이트**합니다. 이 과정은 비밀번호에 따라 **키스트림을 생성**하는 중요한 단계입니다. 각 바이트마다 키가 업데이트되며, **복호화 및 암호화**에 사용되는 **키스트림**을 생성합니다.

#### `update_keys` 함수 설명

```python
def update_keys(self, byte):
    """3개의 키 업데이트"""
    # keys[0]을 CRC32 연산을 통해 업데이트
    self.keys[0] = self.crc32_update(self.keys[0], byte)
    
    # keys[1]은 keys[0]을 기반으로 선형 변환 후 업데이트
    self.keys[1] = ((self.keys[1] + (self.keys[0] & 0xFF)) * 134775813 + 1) & 0xFFFFFFFF
    
    # keys[2]는 keys[1]의 상위 8비트를 사용하여 CRC32 연산으로 업데이트
    self.keys[2] = self.crc32_update(self.keys[2], (self.keys[1] >> 24) & 0xFF)
```

* **`keys[0]`**: 비밀번호의 **각 바이트**마다 `crc32_update` 함수를 이용해 **CRC32 연산**을 진행하여 `keys[0]`을 업데이트합니다.
* **`keys[1]`**: `keys[0]`의 **하위 8비트**를 사용하여 **선형 변환**을 통해 `keys[1]`을 업데이트합니다. 이 선형 변환은 \*\*`134775813`\*\*이라는 상수를 사용하여 `keys[1]`을 갱신합니다.
* **`keys[2]`**: `keys[1]`의 **상위 8비트**를 이용해 다시 **CRC32 연산**을 진행하여 `keys[2]`를 업데이트합니다.

#### `init_keys` 함수 설명

```python
def init_keys(self, password):
    """비밀번호로 키 초기화"""
    self.reset_keys()  # keys[0], keys[1], keys[2]를 초기화
    for byte in password:  # 비밀번호의 각 바이트에 대해 키 업데이트
        self.update_keys(byte)
```

* **`init_keys`** 함수는 **비밀번호**를 받아 **각 바이트**를 `update_keys` 함수에 전달하여 **세 개의 키**(`keys[0]`, `keys[1]`, `keys[2]`)를 **업데이트**합니다.
* 비밀번호가 **6글자**라면, 비밀번호의 **각 바이트**가 `update_keys` 함수에 전달되어 **6번**에 걸쳐 `keys[0]`, `keys[1]`, `keys[2]`가 갱신됩니다.

#### 키 업데이트 흐름

1. **비밀번호 바이트 1 (첫 번째 글자)**:

   * `keys[0]`, `keys[1]`, `keys[2]`는 비밀번호의 첫 번째 바이트를 사용하여 갱신됩니다.
2. **비밀번호 바이트 2 (두 번째 글자)**:

   * `keys[0]`, `keys[1]`, `keys[2]`는 비밀번호의 두 번째 바이트를 사용하여 갱신됩니다.
3. 이 과정이 비밀번호의 **모든 바이트**에 대해 반복됩니다. (비밀번호가 6글자라면 6번 반복)

결과적으로, 비밀번호의 각 바이트는 **세 개의 키**(`keys[0]`, `keys[1]`, `keys[2]`)를 갱신하며, 이를 바탕으로 **키스트림**을 생성하고 복호화에 사용됩니다.

### 비밀번호가 6글자일 때의 흐름

비밀번호가 6글자일 경우, `update_keys`는 **6번** 실행되며 각 실행에서 `keys[0]`, `keys[1]`, `keys[2]`가 업데이트됩니다. 이 키들은 **ZipCrypto 암호화/복호화**의 핵심이며, 각 바이트마다 XOR 연산을 통해 **암호화된 데이터**를 복호화합니다.

1. 첫 번째 글자에 대해 `keys[0]`, `keys[1]`, `keys[2]`가 갱신됩니다.
2. 두 번째 글자에 대해 `keys[0]`, `keys[1]`, `keys[2]`가 갱신됩니다.
3. 세 번째, 네 번째, 다섯 번째, 여섯 번째 글자에 대해 동일하게 갱신됩니다.
4. 최종적으로, **6개의 바이트**를 통해 생성된 `keys[0]`, `keys[1]`, `keys[2]`가 암호화/복호화에 사용됩니다.

* 이 키들은 **암호화된 데이터**를 **XOR 연산**을 통해 복호화하는 데 사용되며, 최종적으로 복호화된 데이터가 원본과 일치하는지 **CRC 값을 비교**하여 확인합니다.

### 1. **암호화된 헤더 복호화 과정**

1. **키스트림 초기화**:

   * `self.init_keys(password)` 함수는 주어진 **비밀번호**를 사용하여 **세 개의 키**(`keys[0]`, `keys[1]`, `keys[2]`)를 초기화합니다. 비밀번호의 각 바이트는 이 키들을 갱신하는 데 사용됩니다. 이 키들로부터 생성된 **키스트림**은 데이터를 복호화하는 데 사용됩니다.

2. **헤더의 첫 11바이트 복호화**:

   * `encrypted_header`는 암호화된 **12바이트** 헤더를 나타냅니다. 이 12바이트 중에서 **첫 11바이트**는 `self.decrypt_byte` 함수를 사용하여 복호화됩니다. 각 바이트는 **키스트림**과 XOR 연산을 통해 복호화됩니다.

3. **체크 바이트 (check byte) 확인**:

   * 12번째 바이트는 \*\*`check_byte_expected`\*\*와 비교할 값입니다. 복호화된 12번째 바이트는 `check_byte`와 비교되며, 만약 이 값이 일치하면 **비밀번호가 맞다는** 것을 의미합니다.

### 2. **체크 바이트와 CRC의 관계**

* **체크 바이트**는 **CRC 체크**와 밀접한 관계가 있습니다.
* CRC는 **데이터 무결성 검사**에 사용되며, Zip 파일에서 **암호화된 데이터**를 복호화한 후 이 데이터를 **검증하는 데 사용**됩니다.
* `check_byte_expected`는 **헤더에 포함된 예상 CRC 값**입니다. 이 값은 복호화된 12번째 바이트와 비교됩니다.

### 복호화 후 체크 바이트 검증 과정

* **헤더 복호화**:

  * `encrypted_header`의 첫 11바이트를 복호화하여, 암호화된 헤더를 평문으로 변환합니다.
* **체크 바이트 복호화**:

  * 마지막 12번째 바이트는 **체크 바이트**로, 이를 복호화하고, `check_byte`와 비교하여 **정확한 복호화가 이루어졌는지** 확인합니다.
* **CRC 체크**:

  * Zip 파일 헤더의 **CRC 값**은 **체크 바이트와 관련**이 있습니다. CRC 값은 헤더의 일부로 저장되며, 파일이 올바르게 복호화되었는지 검증하는 데 사용됩니다.

### 3. **체크 바이트의 역할**

`check_byte`는 비밀번호를 통해 얻어진 키스트림으로 **암호화된 데이터**가 **정상적으로 복호화되었는지** 확인하는 역할을 합니다. `check_byte_expected`는 복호화가 정확하게 이루어졌을 때 예상되는 값으로, 두 값이 일치하면 비밀번호가 맞다는 것을 확인할 수 있습니다.

### 4. **결과**

* **체크 바이트가 일치**하면, **비밀번호가 맞은 것**으로 판단할 수 있습니다. 그렇지 않으면, **암호가 틀린 것**이므로 **다시 시도**해야 합니다.

### 5. **전체 과정 요약**

1. **비밀번호**를 받아 **세 개의 키**(`keys[0]`, `keys[1]`, `keys[2]`)를 초기화합니다.
2. **12바이트 헤더**에서 첫 11바이트를 복호화하고, 12번째 바이트는 `check_byte`와 비교하여 **비밀번호 검증**을 빠르게 수행합니다.
3. **체크 바이트**가 **예상 값**과 일치하면 **비밀번호가 맞다고 판단**합니다.
4. CRC 체크는 **체크 바이트**와 **파일 무결성**을 검증하는 데 중요한 역할을 합니다.

이 과정은 **ZipCrypto** 암호화된 파일에서 **비밀번호를 검증하는 첫 번째 단계**로 사용되며, 실제로 복호화가 이루어지기 전에 **빠르게 암호가 맞는지 확인**할 수 있는 효율적인 방법입니다.

네, **ZipCrypto 암호화** 방식에서는 **CRC 값도 암호화되어** 저장됩니다. 즉, **CRC**는 **암호화된 파일의 일부**로, 파일이 암호화될 때 함께 **암호화**됩니다. 따라서, **복호화하지 않으면 CRC 값**도 **원래 값을 알 수 없**습니다.

### CRC와 암호화

Zip 파일에서 **CRC-32** 값은 파일의 **무결성**을 검증하기 위한 중요한 역할을 합니다. 일반적으로 CRC 값은 파일의 압축된 데이터가 변형되지 않았는지 확인하는 데 사용됩니다. **ZipCrypto 암호화** 방식에서는 이 CRC 값도 **암호화되어** 저장됩니다.

### 복호화 과정에서 CRC 값 사용

Zip 파일에서 암호화된 데이터를 **복호화**할 때는, **헤더에 포함된 암호화된 CRC 값**을 사용하여 데이터가 제대로 복호화되었는지 **검증**합니다.

### 복호화 과정에서의 CRC 체크

1. **암호화된 파일의 헤더**는 **CRC 값**을 포함하고 있으며, 이 값도 **암호화되어** 있습니다.
2. 비밀번호를 **이용하여 키스트림을 생성**하고, 이를 **암호화된 데이터**와 **헤더를 복호화**합니다.
3. 복호화된 데이터에서 **CRC 값을 추출**하고, 이를 **헤더에 저장된 암호화된 CRC 값**과 **비교**합니다.

   * 만약 두 CRC 값이 **일치**하면, 해당 파일이 **정상적으로 복호화되었음**을 확인할 수 있습니다.
   * **일치하지 않으면**, 비밀번호가 **틀렸**다는 것을 의미하며, 복호화가 실패했다는 신호입니다.

### `check_byte`와 CRC

`check_byte`는 **암호화된 12바이트 헤더의 마지막 바이트**로, 실제 CRC 값을 **간접적으로 확인**하는 데 사용됩니다. 이 **check\_byte**는 **복호화**된 값과 비교하여 비밀번호가 맞는지 확인하는 데 사용되며, CRC 값이 **정상적**이면 해당 비밀번호가 **맞다고 판단**합니다.

### 결론

* **CRC 값도 암호화**되어 있으며, 복호화 과정을 통해 **올바른 CRC 값을 얻을 수** 있습니다.
* 복호화된 데이터와 함께 **CRC 값**을 계산하여, 파일의 **무결성**을 확인합니다.
* 암호가 틀리면 CRC 값이 **일치하지 않**아 **복호화가 실패**하게 됩니다.

따라서 **ZipCrypto 암호화**에서는 **CRC 값도 포함된 데이터를 복호화할 때 함께 해독**해야 하고, **정확한 복호화가 이루어졌는지 확인하는 데 사용**됩니다.
