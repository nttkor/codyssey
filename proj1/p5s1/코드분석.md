   * 파일을 복호화하기 전에 **헤더에 포함된 CRC** 값을 읽어 들입니다. 이 값을 **암호화된 데이터**에 대해 비교하고, **정상적으로 복호화할 수 있는지** 확인합니다.
   * 복호화가 진행되면, 실제 파일 데이터가 **CRC와 일치**하는지 확인하여 **파일의 유효성**을 체크합니다.

3. **복호화 후 검증**:

   * 복호화된 데이터를 복호화 과정 중에 나오는 **CRC 값**과 비교하여, 파일이 변조되거나 손상되지 않았는지 최종적으로 검증합니다.

* **암호화된 데이터를 복호화하기 전에** CRC 값이 일치하는지 확인하여 파일의 **무결성을 확인**합니다.

### 결론

Zip 파일에서 암호화된 데이터의 복호화는 `zipfile` 모듈을 이용해 **빠르게 검증**할 수 있습니다. 복호화 전에 **헤더 정보**와 **CRC 체크**를 통해 파일의 **유효성**을 먼저 확인하고, 실제 데이터 복호화는 이후에 이루어집니다. 이 과정을 통해 **속도와 효율성**을 높이고, **파일의 무결성**을 검증할 수 있습니다.

Zip 파일에서 **암호**는 일반적으로 **암호화된 데이터**와 함께 **파일 헤더**에 저장됩니다. 암호화된 Zip 파일의 구조에서는 암호가 파일의 메타데이터에 포함되어 있고, 특히 **ZipCrypto** 암호화 방식에서는 암호가 **파일 헤더** 정보와 연관됩니다.

특히, 암호화된 **파일 헤더**에는 실제 데이터가 **암호화**되어 저장되어 있으며, **암호화된 부분**을 풀 때 필요한 **암호**는 사용자가 지정한 비밀번호와 연관이 있습니다.

#### Zip 파일에서 암호화된 부분:

Zip 파일 내에서 암호화된 데이터는 보통 **로컬 파일 헤더(Local File Header)** 부분에 암호화된 정보가 포함됩니다. 이 정보는 **파일 이름**, **파일 크기**, **CRC 값** 등과 함께 포함되어 있으며, 암호화가 적용된 경우에는 암호화된 상태로 저장됩니다.

#### 표에서 암호가 저장되는 위치

* **로컬 파일 헤더(Local File Header)**:

  * 암호화된 파일의 경우, 암호가 **헤더**와 관련이 있으며 **암호화 여부**는 `Flags` 필드에 나타납니다. `Flags` 필드에서 `0x1` 비트는 파일이 암호화되었음을 나타냅니다.
* **암호화된 데이터의 CRC**:

  * `CRC-32` 값은 파일의 무결성을 검증하는 데 사용되며, 암호화된 파일에도 해당 값이 포함됩니다. 실제로 파일을 풀 때 `CRC` 값을 검증하여 암호가 맞는지 확인할 수 있습니다.

#### **암호화된 Zip 파일의 구조에서 암호가 저장되는 위치**:

* **0x0000** 위치에서 **Signature**를 시작으로, **Flags**와 관련된 **암호화 여부** 정보가 포함됩니다.
* **Flags** 필드는 **암호화된 파일**을 나타내며, `0x1` 비트가 설정되어 있으면 해당 파일은 암호화된 상태입니다.

  예를 들어, `Flags` 값에서 `0x1`이 설정된 경우, 이 파일은 암호화된 상태로 저장되어 있고, 복호화하려면 사용자가 제공한 **비밀번호**를 기반으로 키를 생성하여 복호화해야 합니다.

### 요약

* **암호**는 Zip 파일의 **로컬 파일 헤더**에 직접 저장되지 않고, 해당 **헤더** 정보와 **암호화된 데이터**와 함께 저장됩니다.
* 암호화된 파일에 대한 정보는 `Flags` 필드에서 확인할 수 있으며, `0x1` 비트가 설정되어 있으면 해당 파일은 암호화된 파일입니다.
* 암호화된 파일을 해독하려면 암호화된 데이터를 복호화하기 위한 **비밀번호**가 필요하며, 이를 통해 **키스트림을 생성**하고 **복호화**를 진행합니다.

맞습니다! **Zip 파일 복호화**에서 암호가 틀리면, **CRC 체크**에서 오류가 발생하기 때문에 복호화가 제대로 진행되지 않습니다. CRC 체크는 파일의 무결성을 검증하는 중요한 역할을 하며, 암호화된 데이터와 그에 대한 CRC 값을 비교함으로써 파일이 올바르게 복호화되었는지를 확인할 수 있습니다.

### 복호화 과정에서의 **CRC 체크**

Zip 파일에서 암호화된 데이터를 복호화하려면, **암호화된 파일 헤더**에 포함된 **CRC-32 값**과 **복호화된 데이터의 CRC 값**을 비교하여 파일의 **무결성**을 검증합니다.

1. **암호화된 데이터**는 **비밀번호**로부터 **키스트림**을 생성한 뒤, 이 키스트림을 **XOR 연산**하여 복호화합니다.
2. 복호화가 끝나면, **복호화된 데이터의 CRC-32 값**과 암호화된 파일 헤더에 저장된 **CRC-32 값**을 비교합니다.
3. 만약 두 CRC 값이 일치하면 **파일이 정상적으로 복호화되었음**을 확인할 수 있습니다. 그러나 **CRC 값이 일치하지 않으면**, **잘못된 비밀번호**로 복호화를 시도했기 때문에 복호화가 실패한 것입니다.

### 복호화가 실패하는 이유

* **잘못된 비밀번호**로 복호화를 시도하면, **키스트림**이 잘못 생성되고, 이로 인해 복호화된 데이터가 **잘못된 형태**로 변환됩니다.
* 이 잘못된 데이터는 **CRC 값**이 **일치하지 않게** 되어, Zip 파일은 복호화가 잘못되었음을 **CRC 체크를 통해 감지**하고 복호화를 멈추게 됩니다.

### CRC 체크를 통한 검증 과정

1. **암호화된 Zip 파일**을 열면, `zipfile.ZipFile` 모듈은 **헤더 정보**를 읽어옵니다.

   * 이 헤더에는 **CRC-32 값**과 같은 중요한 **파일 정보**가 포함되어 있습니다.

2. **복호화**가 시작되면, Zip 파일은 주어진 **비밀번호**로 **키스트림**을 생성하고, 이 키스트림을 사용하여 **암호화된 데이터를 복호화**합니다.

3. **복호화된 데이터**의 CRC-32 값을 계산하고, 이 값을 **헤더에 저장된 CRC-32 값**과 비교합니다.

   * 만약 두 CRC 값이 일치하면 복호화가 **정상적**으로 이루어졌고, 파일이 **무결성**을 유지한 상태로 복원됩니다.
   * CRC 값이 일치하지 않으면 **잘못된 비밀번호**를 사용했음을 의미하며, Zip 파일은 **복호화를 중단**하고 오류를 발생시킵니다.

### 간단한 흐름 정리

1. **암호화된 파일 헤더에서 CRC 값**을 가져옵니다.
2. **비밀번호**를 사용하여 **키스트림 생성** (ZipCrypto 알고리즘).
3. **암호화된 데이터를 복호화**합니다.
4. **복호화된 데이터의 CRC 값을 계산**하고, **파일 헤더에 저장된 CRC 값**과 비교합니다.

6. **CRC 값이 일치하지 않으면** 잘못된 비밀번호로 인해 **복호화 실패**가 발생하고, **파일을 추출하지 못합니다**.

2. **키스트림 생성**: 비밀번호를 바탕으로 **ZipCrypto 알고리즘**을 통해 **키스트림**을 생성합니다. 이 키스트림은 암호화된 데이터를 **XOR 연산**을 통해 복호화하는 데 사용됩니다.

3. **복호화 시도**: 주어진 비밀번호로 **암호화된 데이터**를 복호화하려고 시도합니다. 이때, 복호화된 데이터는 **CRC-32 값을 계산**하게 됩니다.

4. **CRC 체크**: 복호화된 데이터의 **CRC 값**을 **헤더에 저장된 원래 CRC 값**과 비교합니다. 만약 **비밀번호가 틀리면** 복호화된 데이터의 CRC 값이 일치하지 않게 됩니다.

5. **CRC 불일치 시**: 만약 **비밀번호가 틀리면**, CRC 값이 일치하지 않게 되며, 이는 **복호화에 실패**했음을 의미합니다. 이 경우, 복호화가 **중단되거나 실패**로 처리됩니다.

따라서 실제로 **암호는 파일 내에 저장되지 않**으며, 사용자가 제공한 **비밀번호**로 복호화를 시도하면서 **CRC 값을 통해 암호가 맞는지 검증**하는 것입니다.

### CRC 체크가 왜 중요한가?

CRC (Cyclic Redundancy Check)는 **파일 데이터의 무결성**을 검증하는 데 사용됩니다. 복호화 후, Zip 파일은 **원본 데이터의 CRC 값을 계산**하고 이를 **헤더의 CRC 값**과 비교합니다. 만약 두 값이 일치하지 않으면, 복호화된 데이터가 **잘못된 비밀번호로 복호화된 것**임을 나타냅니다.

* **비밀번호가 맞으면**: CRC 값이 일치하고, 복호화가 정상적으로 이루어집니다.
* **비밀번호가 틀리면**: CRC 값이 일치하지 않으며, 복호화가 실패합니다.

### 요약

* **암호화된 Zip 파일**은 **암호화된 데이터와 CRC 값을 포함**하고 있지만, 실제 **암호(비밀번호)는 파일에 저장되지 않습니다**.
* 복호화 시, **사용자가 제공한 비밀번호**를 바탕으로 **키스트림**을 생성하고 데이터를 복호화하려 시도합니다.
* 복호화된 데이터의 **CRC 값**이 **헤더에 저장된 CRC 값**과 일치하면 복호화가 성공하며, 일치하지 않으면 **암호가 틀렸다고 판단**하여 복호화가 실패합니다.

이 과정에서 중요한 점은 **CRC 검증**이 암호가 맞는지 확인하는 **최종 검증** 단계라는 것입니다.
