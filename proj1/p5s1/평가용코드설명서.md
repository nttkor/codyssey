## 코드 설명서: **ZipCrypto 암호화 해독 (비밀번호 검증)**

### 1. **`check_password_fast` 함수 개요**

이 함수는 주어진 **비밀번호**가 **ZipCrypto 암호화 방식**으로 암호화된 **헤더 정보**를 정확하게 복호화할 수 있는지 **빠르게 검증**하는 기능을 수행합니다. 비밀번호가 올바르면 **체크 바이트**가 **예상 값과 일치**하는지 확인하는 방식으로 **빠른 검증**을 수행합니다.

### 2. **`check_password_fast` 함수 흐름**

#### (1) **비밀번호 초기화 및 키스트림 생성** (`self.init_keys` 호출)

```python
self.init_keys(password.encode() if isinstance(password, str) else password)
```

* **`self.init_keys(password)`**:

  * 이 함수는 주어진 **비밀번호**를 이용해 **세 개의 키**(`keys[0]`, `keys[1]`, `keys[2]`)를 초기화합니다.
  * **비밀번호 바이트**마다 `self.update_keys()` 함수가 호출되어 세 개의 키를 **갱신**하고, 이 갱신된 키들로 **키스트림**을 생성합니다.
  * 비밀번호를 **바이트 배열**로 변환하여 **키스트림**을 생성하는 과정을 통해 **암호화된 데이터**를 복호화할 수 있는 **키가 준비**됩니다.

#### (2) **암호화된 헤더에서 첫 11바이트 복호화**

```python
for i in range(11):
    self.decrypt_byte(encrypted_header[i])
```

* **헤더 복호화**:

  * Zip 파일의 **12바이트 헤더**에서 **첫 11바이트**를 복호화합니다.
  * 복호화는 **XOR 연산**을 사용하여 `self.decrypt_byte()` 함수가 하나씩 수행합니다. 이때 **키스트림**은 비밀번호로 초기화된 **세 개의 키**를 바탕으로 생성됩니다.
  * `self.decrypt_byte()`는 **XOR 연산**을 사용하여 **암호화된 바이트**를 **평문으로 변환**하는 함수입니다.

#### (3) **체크 바이트 복호화 및 검증**

```python
check_byte = self.decrypt_byte(encrypted_header[11])
return check_byte == check_byte_expected
```

* **체크 바이트 복호화**:

  * 12번째 바이트는 **체크 바이트**로, 이 값을 복호화하여 **예상된 값**(`check_byte_expected`)과 비교합니다.
  * **체크 바이트**는 **CRC-32 값**을 간접적으로 나타내는 값이며, **암호화된 데이터**가 정확하게 복호화되었는지 확인하는 데 사용됩니다.
* **체크 바이트 검증**:

  * 복호화된 **12번째 바이트**(`check_byte`)와 **예상된 체크 바이트**(`check_byte_expected`)가 **일치**하면, **비밀번호가 맞다는 것**을 의미합니다.
  * 일치하지 않으면 **비밀번호가 틀린 것**이므로, 복호화가 실패한 것으로 간주합니다.

### 3. **핵심 함수 설명**

#### (1) **`init_keys` 함수**: 비밀번호로 키 초기화

```python
def init_keys(self, password):
    """비밀번호로 키 초기화"""
    self.reset_keys()
    for byte in password:
        self.update_keys(byte)
```

* **`self.reset_keys()`**:

  * 이 함수는 **세 개의 키**(`keys[0]`, `keys[1]`, `keys[2]`)를 **초기값**으로 리셋합니다. 기본 값은 `0x12345678`, `0x23456789`, `0x34567890`입니다.
* **`for byte in password`**:

  * 주어진 비밀번호의 **각 바이트**마다 `update_keys(byte)` 함수를 호출하여 **세 개의 키**를 갱신합니다.
* **`update_keys(byte)`**:

  * `update_keys` 함수는 각 **바이트**를 사용하여 **세 개의 키**(`keys[0]`, `keys[1]`, `keys[2]`)를 **갱신**합니다. 이 갱신된 키들은 **키스트림을 생성**하는 데 사용됩니다.

#### (2) **`update_keys` 함수**: 키 갱신

```python
def update_keys(self, byte):
    """3개의 키 업데이트"""
    self.keys[0] = self.crc32_update(self.keys[0], byte)
    self.keys[1] = ((self.keys[1] + (self.keys[0] & 0xFF)) * 134775813 + 1) & 0xFFFFFFFF
    self.keys[2] = self.crc32_update(self.keys[2], (self.keys[1] >> 24) & 0xFF)
```

* **`crc32_update`**:

  * 이 함수는 **CRC32 연산**을 통해 각 키를 **업데이트**합니다. 각 바이트에 대해 **키**를 변환하여 **키스트림을 동적으로 생성**합니다.
* **`keys[0]`**, **`keys[1]`**, **`keys[2]`**:

  * **`keys[0]`**: CRC32 연산을 사용하여 키를 업데이트합니다.
  * **`keys[1]`**: `keys[0]`의 **하위 8비트**를 사용하여 **선형 변환** 후 업데이트합니다.
  * **`keys[2]`**: `keys[1]`의 **상위 8비트**를 사용하여 **다시 CRC32 연산**을 수행하여 업데이트합니다.

#### (3) **`decrypt_byte` 함수**: 한 바이트 복호화

```python
def decrypt_byte(self, enc_byte):
    """한 바이트 복호화"""
    temp = (self.keys[2] & 0xFFFF) | 2
    keystream = ((temp * (temp ^ 1)) >> 8) & 0xFF
    plain = enc_byte ^ keystream
    self.update_keys(plain)
    return plain
```

* **XOR 연산**:

  * `decrypt_byte` 함수는 암호화된 **한 바이트**를 복호화합니다. 복호화는 **키스트림**과 **XOR 연산**을 사용하여 이루어집니다.
* **키스트림 생성**:

  * `keystream`은 `keys[2]`를 기반으로 계산된 **키스트림**입니다. 이 **키스트림**을 사용하여 **암호화된 바이트**(`enc_byte`)와 **XOR 연산**을 하여 복호화된 데이터를 반환합니다.

### 4. **이론 설명**

#### **ZipCrypto 암호화와 복호화**:

* **ZipCrypto**는 **대칭키 암호화 방식**을 사용합니다. 즉, 동일한 키를 사용하여 **암호화**와 **복호화**를 모두 처리합니다.
* 이 암호화 방식은 **세 개의 키**(`keys[0]`, `keys[1]`, `keys[2]`)를 사용하여 **키스트림**을 생성하고, 이 키스트림을 **XOR 연산**에 사용하여 **데이터를 복호화**합니다.
* 비밀번호가 주어지면 **키스트림 생성**에 필요한 **세 개의 키**가 **비밀번호에 따라 업데이트**됩니다.

#### **CRC 체크**:

* \*\*CRC (Cyclic Redundancy Check)\*\*는 **데이터 무결성**을 확인하는 데 사용됩니다. 복호화된 데이터의 **CRC 값**이 헤더에 저장된 CRC 값과 일치하면 **복호화가 정확하게 이루어졌**다고 확인할 수 있습니다.
* **체크 바이트**는 복호화가 정확히 이루어졌는지 확인하는 중요한 지표로 사용됩니다.

### 5. **전체 흐름 요약**

1. **비밀번호 입력** → 비밀번호로 **세 개의 키**(`keys[0]`, `keys[1]`, `keys[2]`) 초기화.
2. **12바이트 헤더**의 첫 11바이트를 **XOR 연산**을 사용하여 복호화.
3. **12번째 바이트** (체크 바이트) 복호화 → 예상한 체크 바이트와 비교하여 **비밀번호 검증**.
4. **체크 바이트**가 일치하면 비밀번호가 **맞다는 것**을 확인.

멀티태스킹 부분과 암호를 발생하고 분해하는 과정은 ZipCrypto의 복호화에서 **병렬 처리**를 이용해 비밀번호를 빠르게 찾도록 하는 중요한 역할을 합니다. 이 과정에서 여러 **워커 프로세스**가 **암호**를 찾아내고, 모든 프로세서가 작업을 종료하는 방식에 대해 설명해드리겠습니다.

### 1. **멀티태스킹을 활용한 비밀번호 해독**

멀티태스킹을 사용하여 여러 **프로세스**를 동시에 실행함으로써, 비밀번호를 찾는 시간을 **단축**할 수 있습니다. **각 프로세스**는 **다른 범위의 비밀번호**를 시도하며, **병렬로 작업**을 진행합니다. 각 프로세스는 비밀번호를 시도하면서, **큐**를 통해 **공유된 결과**를 부모 프로세스에게 전달합니다.

#### 1.1. **`Pool`을 이용한 병렬 처리**

```python
with Pool(processes=max_workers) as pool:
    results = pool.map_async(worker_process_improved, tasks)
```

* **`Pool`**: `multiprocessing` 모듈에서 제공하는 **`Pool`** 클래스는 여러 프로세스를 **동시 실행**할 수 있게 합니다.
* **`tasks`**: 각 워커 프로세스에 할당할 **작업 단위**입니다. 예를 들어, 비밀번호 리스트에서 서로 다른 범위를 할당하여 병렬로 처리합니다.
* **`pool.map_async()`**: `async`로 비동기적으로 **작업을 분배**하고, 모든 작업이 완료될 때까지 기다립니다. 비밀번호를 찾기 위한 워커들이 동시에 작업을 진행하게 됩니다.

#### 1.2. **워커 프로세스** (`worker_process_improved`)

```python
def worker_process_improved(args):
    worker_id, zip_path, encrypted_header, check_byte, queue, total_workers = args
    validator = ZipCryptoValidator()
    count = 0
    start_time = time.time()
    last_print_time = start_time
    
    password_gen = smart_password_generator()
    skip_count = 0
    for password in password_gen:
        if skip_count % total_workers != worker_id:
            skip_count += 1
            continue
            
        count += 1
        skip_count += 1
        
        if validator.check_password_fast(password, encrypted_header, check_byte):
            # 실제 ZIP 파일로 최종 검증
            try:
                with zipfile.ZipFile(zip_path) as zf:
                    zf.extractall(pwd=password.encode())
                queue.put(password)
                return password
            except:
                pass
```

* **`worker_process_improved`**: 각 **워커 프로세스**는 주어진 **비밀번호 목록**에서 비밀번호를 하나씩 시도하여 **빠른 검증**을 수행하고, **암호가 맞는지 확인**합니다.
* **`password_gen`**: `smart_password_generator()`는 다양한 **패턴의 비밀번호**를 생성하는 제너레이터로, 가장 가능성이 높은 비밀번호부터 차례대로 생성하여 시도합니다.
* **`check_password_fast()`**: 비밀번호가 맞는지 확인하기 위해 헤더를 빠르게 복호화하고 **체크 바이트**를 비교하여 비밀번호를 검증합니다.


네, 맞습니다! 이 부분이 바로 **인터리빙**(interleaving) 기법을 적용한 코드입니다. 인터리빙은 여러 작업을 **병렬로** 수행할 때, 각 워커가 **다른 범위의 작업**을 처리하도록 하여 **동시 작업**을 효율적으로 나누는 기법입니다.

### **인터리빙 (Interleaving) 부분 설명**

이 코드는 여러 워커 프로세스가 **동시 작업**을 하면서, 각 프로세스가 **서로 다른 비밀번호**를 시도하도록 만들어줍니다. **인터리빙** 방식은 각 워커가 **순차적으로** 비밀번호를 시도하는 대신, 워커들의 **작업을 나누어** 병렬적으로 실행하는 방식입니다.

### 코드 분석

```python
for password in password_gen:
    if skip_count % total_workers != worker_id:
        skip_count += 1
        continue
```

#### 1. **`password_gen` 제너레이터**

```python
password_gen = smart_password_generator()
```

* \*\*`password_gen`\*\*은 `smart_password_generator()` 함수를 통해 생성된 **비밀번호 제너레이터**입니다. 이 제너레이터는 **가능성 높은 순서**대로 비밀번호를 생성합니다.

#### 2. **`skip_count % total_workers != worker_id`**

```python
if skip_count % total_workers != worker_id:
    skip_count += 1
    continue
```

* **`skip_count`**: 이 변수는 **각 워커가 검사한 비밀번호의 수**를 추적합니다. 각 워커는 자기 할당된 비밀번호를 차례대로 처리하며, `skip_count`는 각 워커가 건너뛰어야 할 비밀번호의 수를 관리합니다.

* **`total_workers`**: 전체 **워커 프로세스의 수**입니다. 이 값을 통해 각 워커가 처리할 **비밀번호의 범위**를 나누게 됩니다.

* **`worker_id`**: 현재 워커 프로세스의 **고유 ID**입니다. 각 워커가 처리해야 할 **비밀번호 범위**를 계산하는 데 사용됩니다.

* **`skip_count % total_workers != worker_id`**:

  * 이 조건은 **워커 프로세스가 고유한 범위의 비밀번호만 처리**하도록 합니다. 예를 들어, 만약 4개의 워커가 있다면, 워커 1은 **1, 5, 9, 13...** 번째 비밀번호를 처리하고, 워커 2는 **2, 6, 10, 14...** 번째 비밀번호를 처리하게 됩니다.
  * `skip_count`는 **비밀번호 순서**를 나타내며, `total_workers`와 **나머지 연산**을 통해 각 워커가 처리할 비밀번호를 **인터리빙** 방식으로 나누게 됩니다.

#### 3. **`skip_count += 1` 및 `continue`**

```python
skip_count += 1
continue
```

* **`skip_count += 1`**: `skip_count` 값을 증가시켜, 워커가 처리한 비밀번호의 수를 기록합니다.
* **`continue`**: 조건이 만족되면 **다음 비밀번호로 넘어가게** 하고, 현재 비밀번호는 처리하지 않습니다. 이를 통해 각 워커가 자신에게 할당된 비밀번호만 처리하게 됩니다.

### 3. **작동 방식**

* 워커 1은 **1, 5, 9, 13...** 번째 비밀번호를 처리하고,
* 워커 2는 **2, 6, 10, 14...** 번째 비밀번호를 처리하는 방식으로 각 워커가 **자기 범위의 비밀번호**만 검사합니다.

이렇게 **인터리빙** 기법을 사용하면 **동시 작업**이 가능해지고, **각 프로세스**가 **병렬적으로 작업**을 나누어 하므로 비밀번호를 찾는 **속도**가 빨라집니다.

### 4. **전체적인 흐름**

1. \*\*`password_gen`\*\*은 비밀번호를 순차적으로 생성합니다.
2. 각 **워커**는 **인터리빙 방식**으로 **자기 할당된 비밀번호 범위**만 처리합니다.
3. \*\*`skip_count % total_workers != worker_id`\*\*를 통해 각 워커가 할당된 범위의 비밀번호만 시도하고, 나머지 비밀번호는 건너뛰게 됩니다.
4. 이 방식을 통해 **워커 프로세스**가 병렬로 작업을 처리하므로, 여러 개의 비밀번호를 동시에 시도할 수 있어 **암호를 빠르게 찾을 수** 있습니다.

### 5. **인터리빙 기법의 장점**

  * 예를 들어, `itertools.product(chars + digits, repeat=remaining_len)`은 **문자 + 숫자** 조합으로 가능한 **모든 비밀번호**를 생성합니다.

### `yield` 키워드의 역할

* \*\*`yield`\*\*는 이 함수가 **제너레이터**로 동작하게 만듭니다. 이 방식은 **메모리 효율적**이고 \*\*지연 평가(lazy evaluation)\*\*가 가능합니다. 즉, 각 비밀번호를 **하나씩 생성**하고 **검사**할 때마다 **한 번에 하나씩 반환**합니다.
* \*\*`yield`\*\*는 함수의 실행을 **중단하지 않고** 그 상태를 유지한 채 **다음 값을 생성**할 수 있게 해줍니다.

### `smart_password_generator()`의 강점

1. **효율적인 비밀번호 시도**:

   * **통계적으로 높은 확률**을 가진 비밀번호부터 시도함으로써 **빠르게 정답을 찾을 가능성**이 높습니다.
   * 비밀번호 조합의 순서를 **단순히 랜덤**으로 시도하는 것이 아니라, 사람들이 자주 사용하는 **패턴을 우선적으로 시도**하여 효율성을 높입니다.

2. **범위가 넓지 않지만, 많은 경우 유효**:

   * 실제로 많은 사람들이 **간단한 패턴**이나 **일반적인 숫자 조합**을 사용하기 때문에, 이 **스마트한 접근법**은 상당히 유효합니다. 예를 들어, `admin123`, `password1`과 같은 비밀번호는 매우 자주 사용되므로 이를 **우선적으로 시도**하는 것이 매우 효율적입니다.

3. **유동적인 비밀번호 생성**:

   * 비밀번호가 `pass123`, `test12`처럼 **숫자가 뒤에 붙은 형태**가 많기 때문에, 그런 패턴을 먼저 시도하는 방식은 **많은 공격 시나리오에서 유효**합니다.

### 결론

* `smart_password_generator()` 함수는 **가능성 높은 비밀번호**를 **효율적으로 생성**하는 알고리즘으로, **ZipCrypto 복호화**에서 **빠르게 정답을 찾을 수 있는 방법**을 제공합니다.
* 이 함수는 **고정된 패턴**이나 **자주 사용되는 조합**을 우선적으로 시도하여 비밀번호를 찾을 가능성을 극대화하며, 이를 통해 전체 **브루트포스 공격**을 **효율적으로 최적화**합니다.
