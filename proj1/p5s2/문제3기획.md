좋아요. 올려주신 두 개의 .ui(기본형 `caculator.ui`, 공학형 `engineering.ui`)를 기준으로 “계산은 아직 하지 않고, 버튼을 누를 때마다 화면에 숫자/연산자(함수 이름)만 누적 표기되는” 앱으로 개조하는 **설계/기획 의도**를 정리해요. (제가 UI 파일을 확인했는데, 두 UI 모두 `led`라는 QLineEdit 디스플레이가 있고, 공통으로 `btn_mode`가 있습니다. 공학형에는 `sin, cos, tan, ln, log₁₀, x!, x², x³, x^y, e^x, 10^x, 1/x, 2√x, 3√x, y√x, π, Rand, sinh, cosh, tanh` 같은 버튼들이 있고 숫자/사칙/괄호/백스페이스/AC도 있습니다.)

# 목표

1. **기본 화면**은 `engineering.ui`
2. **왼쪽 아래 Mode 버튼**을 누르면 `engineering.ui ↔ caculator.ui`가 **즉시 교체**
3. **계산은 하지 않음**: 버튼을 누를 때마다 `led`에 **숫자/연산자/함수명이 누적 표시**
4. 공학용 버튼은 **계산 없이 “표시만”** (예: `sin` 누르면 `sin(`가 붙음)
5. 나중에 계산 엔진을 붙일 수 있도록 **표현(토큰)과 계산 로직을 분리**

# 전체 구조(Controller + 두 화면 동시 생성, 한 화면만 표시)

* **AppController(중앙 컨트롤러)**

  * 앱의 **단일 진입점**.
  * **표시 버퍼(expression\_buffer)**: 사용자가 누른 내용을 **문자열로 누적**(예: `"12+sin(3)"`).
  * **상태**: 현재 모드(ENGINEERING/BASIC), 2nd 상태(필요 시), 각종 토글(Rad/Deg 등은 당장은 텍스트만).
  * **UI 어댑터**: 두 UI(`EngineeringWindow`, `BasicWindow`)를 **동시에 생성**해 두고, **하나만 show()**. Mode 버튼을 누르면 **현재 창 hide → 반대 창 show**.
  * **단일 이벤트 라우팅**: 모든 버튼 클릭을 \*\*AppController의 `on_button(token)`\*\*으로 전달.
  * **디스플레이 동기화**: 모드 전환 시 새로 보여줄 창의 `led`에 **현재 expression\_buffer 그대로 세팅**(+ 폰트 동적 크기 조절).

* **UI 레이어**

  * `EngineeringWindow`: `engineering.ui` 로드.
  * `BasicWindow`: `caculator.ui` 로드.
  * 각 창은 **자기 안의 모든 QPushButton을 자동 수집**하고, 컨트롤러가 제공하는 **토큰 매핑 규칙**대로 `clicked → on_button(token)`을 연결.
  * 두 창 모두 `led`의 objectName가 동일(`led`)이므로, 컨트롤러는 **현재 활성 창의 led**만 갱신하면 OK.
  * \*\*Mode 버튼(objectName: `btn_mode`)\*\*은 두 창 모두에서 \*\*컨트롤러의 `toggle_mode()`\*\*에 연결.

> 왜 두 창을 동시에 생성?
>
> * 최상위가 둘 다 QMainWindow라 한 창 안에 다른 창을 끼우기보다, **두 창을 만들어 놓고 show/hide**가 가장 간결하고 안전합니다.
> * 교체 시 상태/표현을 유지하기 쉬움(버퍼만 다시 렌더).

---

# 이벤트/표현 설계(“표시만” 하는 단계)

* **버퍼 정책**

  * 모든 입력은 **문자열 버퍼**(예: `self.expression_buffer`)에 **그대로 이어붙임**.
  * 디스플레이는 항상 버퍼를 그대로 반영(오류 처리 없음).
  * **백스페이스**는 **문자 단위로 1글자 삭제**(함수 토큰(`sin(`)도 결국 문자의 집합).
  * **AC**는 버퍼를 `""`로 초기화하고 디스플레이 `0`.
  * \*\*=\*\*도 계산하지 않고 **문자 `=`를 붙일지**, 혹은 **무시**할지 정책 선택:

    * 추천: **`=` 입력 시 버퍼 끝에 `=` 추가**(사용자가 누른 사실을 보여줌). 나중에 계산 엔진 붙일 때 이 토큰을 트리거로 삼을 수 있음.

* **토큰 매핑 원칙**

  * **숫자/소수점/사칙/괄호**: 버튼 텍스트 그대로(`0-9`, `.`, `+`, `-`, `*`, `/`, `(`, `)`)
  * **상수**: `π` → `π`(또는 `pi`), `e` 버튼이 있으면 `e`.
  * **함수형(괄호가 필요)**: `sin, cos, tan, sinh, cosh, tanh, ln, log₁₀, rand` 등은 \*\*`함수명 + "("`\*\*를 붙여 바로 **열린 괄호**까지 삽입 (예: `sin(`, `ln(`, `rand(`).
  * **멱/루트류**:

    * `x²` → `^2`
    * `x³` → `^3`
    * `x^y` → `^` (사용자가 뒤에 y를 직접 입력)
    * `e^x` → `e^`
    * `10^x` → `10^`
    * `1/x` → `1/(` (뒤에 `x`를 사용자가 넣도록) *혹은* `1/`만 붙이되 일관성 유지
    * `2√x` → `2√(`, `3√x` → `3√(`, `y√x` → `√(` 또는 `root(`로 통일(표시 목적이므로 가독성 우선)
  * **팩토리얼**: `x!` → `!`(후치 연산자이므로 버퍼 마지막에 `!`만 추가)
  * **메모리키**: `MC, M+, M-, MR`은 **그대로 “텍스트”를 버퍼에 추가**(계산/메모리 동작은 나중에)
  * **RAD/DEG**: 현재는 계산이 없으니 **토글될 때 버퍼에 `Rad`/`Deg` 텍스트를 덧붙이기보다는 상태만 UI로 표시**하는 게 깔끔하지만, 요청대로 “표시”가 목적이면 `[Rad]`같은 꼬리표를 **한 번만** 넣는 방향도 가능(중복 삽입 방지 필요).

* **2nd(세컨드) 키**

  * 1단계에서는 **그냥 `2nd` 텍스트를 버퍼에 추가**(최소 구현).
  * 향후에는 `2nd` 활성화 시 **버튼 라벨/토큰 맵을 교체**(예: `sin ↔ asin`)하는 설계로 확장.

# 신호 연결(보일러플레이트 제거 전략)

* 버튼이 많으니, **규칙 기반 자동 연결**:

  1. 현재 창에서 **모든 QPushButton**을 `findChildren`으로 수집
  2. 각 버튼의 `objectName` 또는 `text`로 **토큰을 결정**
  3. 공통/예외 매핑 딕셔너리로 처리:

     * 예: `{"btn_plus": "+", "btn_minus": "-", "btn_decimal": ".", "btn_open_paren": "(", "btn_close_paren": ")" ...}`
     * 함수/특수키: `{"btn_sin": "sin(", "btn_ln": "ln(", "btn_x_squared": "^2", "btn_x_factorial": "!", "btn_rand": "rand(" ...}`
  4. 예외키(`AC`, `backspace`, `mode`)는 **전용 핸들러**에 연결
* 가능하면 Qt Designer에서 각 버튼의 **property에 “token”**(예: `sin(`, `^2`)을 미리 심어두고, 코드에서는 **그 값을 읽어서 바로 연결**하면 매핑 딕셔너리를 대폭 줄일 수 있음.

# 1) 토큰 매핑 표 (표시는 버퍼에 누적)

## 기본(공통)

| 버튼 라벨        | 버퍼에 붙일 토큰   | 비고                  |
| ------------ | ----------- | ------------------- |
| 0–9          | `동일`        | 숫자 그대로              |
| .            | `.`         | 소수점                 |
| +            | `+`         |                     |
| -            | `-`         |                     |
| X 또는 ×       | `X`(또는 `×`) | 버튼 텍스트 그대로 쓰는 것을 권장 |
| /            | `/`         |                     |
| (            | `(`         |                     |
| )            | `)`         |                     |
| %            | `%`         | 계산하지 않고 기호만 표시      |
| +/-          | `±`         | 토글 대신 표시만(문자 추가)    |
| =            | `=`         | 계산하지 않고 문자만 추가      |
| AC           | —           | 버퍼 초기화, 디스플레이 `0`   |
| ⌫(Backspace) | —           | 버퍼 마지막 **1문자 삭제**   |

| tanh                 | `tanh(`                     | 〃                       |
| ln                   | `ln(`                       | 〃                       |

| 10^x                 | `10^`                       |                         |
| 1/x                  | `1/(`                       | 뒤에 값은 사용자가 입력           |
| √x / ²√x / ³√x / y√x | `√(` / `2√(` / `3√(` / `√(` | 표시 일관성용                 |
| x!                   | `!`                         | 후치 연산자이므로 `!`만 추가       |
| MR / M+ / M- / MC    | `MR` / `M+` / `M-` / `MC`   | 텍스트만 누적                 |
| DEG/RAD              | (버퍼에 추가하지 않음)               | **상태 표시만**(버퍼 오염 방지 권장) |
| 2nd                  | `2nd`                       | 1차 버전은 표시만(토글 기능은 차후)   |

> 루트/멱/역수류는 “표시 목적”이므로 사람이 알아볼 수 있게 간단 토큰으로 통일했습니다.
> `DEG/RAD`는 버퍼를 지저분하게 만들 수 있어 **버퍼 추가 없이 UI 배지로만 표시**를 권장합니다.

# 2) 자동 연결 규칙(보일러플레이트 최소화)

1. **버퍼/표시 공통 처리**

* 전역 `expression_buffer: str`
* 누를 때마다 `expression_buffer += token` → `led.setText(expression_buffer)`
* 비어 있으면 `led`는 `"0"`
* 글자 수 기반 폰트 스케일 재사용

2. **버튼 수집 & 연결**

* 각 창에서 `findChildren(QPushButton)`로 모든 버튼 수집
* 아래 우선순위로 핸들러 연결:

  * **특수키**: `AC → on_ac()`, `Backspace → on_backspace()`, `Mode → toggle_mode()`, `= → on_equal()`
  * **정규화 매핑 딕셔너리** 존재 시 그 토큰으로 `on_token(token)`
  * **기본 규칙**:

    * 숫자/기호( `0-9.+-/()%` )는 **라벨 그대로** `on_token(btn.text())`
    * 함수명 라벨(정규식 `^[a-zA-Z]+h?$|^ln$|^log\d*$|^rand$`)은 `on_token(f"{name}(")`
* **예외 라벨**(예: `x², x³, x^y, 1/x, √x, x!`)은 딕셔너리로 명시 매핑

3. **모드 전환**

* 앱 시작 시 `EngineeringWindow`와 `BasicWindow` **둘 다 생성**, 하나만 `show()`
* `toggle_mode()`:

  * 현재 창 `hide()` → 다른 창 `show()`
  * 새 창의 `led`에 `expression_buffer` 그대로 표시 + 폰트 리스케일
  * 포커스 이동

4. **특수 동작**

* `AC`: `expression_buffer = ""`, `led="0"`
* `Backspace`: `expression_buffer = expression_buffer[:-1]` (빈 문자열이면 `led="0"`)
* `=`: `expression_buffer += "="` (계산 없음)
