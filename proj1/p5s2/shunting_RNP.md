# [셔닝야드 RPN](https://eunjinii.tistory.com/58)

좋은 질문이에요 👍
말한 방식은 흔히 \*\*연산자 우선순위 기반의 직접 평가 (precedence climbing, or 반복 스캔 방식)\*\*이에요. 즉:

1. 문자열을 왼쪽에서 오른쪽으로 읽으면서
2. 현재 토큰을 쌓아두고
3. 우선순위가 높은 연산자부터 처리 → 다시 전체 식을 스캔하면서 단계적으로 계산
4. 결국 한 값이 남음

이 방법은 코드가 단순해 보일 수 있고, 작은 계산기라면 충분히 동작합니다.

---

## 왜 지금 코드는 셔닝야드(RPN)를 썼을까?

1. **괄호 처리의 안정성**

   * 괄호가 중첩된 경우, 단순 왼→오 스캔은 매번 괄호 깊이에 따라 재귀적/반복적 처리가 필요.
   * RPN 변환은 괄호를 스택으로 관리해서 깔끔히 해결.

2. **함수와 후위 연산**

   * `sin(30)`, `5²`, `(2+3)%` 같은 건 “순차 처리” 방식으론 꽤 까다롭습니다.
   * 셔닝야드는 **함수/후위 연산도 스택에 자연스럽게 들어감** → 구현 일관성이 좋아요.

3. **확장성**

   * 새로운 연산자(예: `^` 거듭제곱)나 다른 함수 추가 시
   * 우선순위만 딕셔너리에 넣으면 끝.

---

## 단순 스캔 방식의 장단점

### 장점

* 구현 코드 짧음 (특히 + - \* / 만 지원할 때).
* 직관적으로 “왼쪽에서 오른쪽”으로 계산하는 게 눈에 보임.
* 간단한 과제/실습용으로는 충분.

### 단점

* 괄호와 함수 지원 시 복잡해짐:

  * `sin(2+3*4)` → `3*4` 먼저 → `2+(...)` → `sin(...)`
* 후위 연산자 처리 불편:

  * `2²+3` 같은 건 `²`를 만나면 직전에 읽은 토큰을 다시 바꿔야 함.
* 연산자 우선순위가 늘어날수록 `while` 루프나 if 블록이 길어짐.

---

## 결론: 여기서 못 쓰는 건 아님

* 지금 코드도 `Calculator._to_rpn()` 대신
  “왼→오 스캔하면서 \*,/ 먼저 계산 → 그다음 +,- 계산” 같은 루프를 구현하면 동작은 합니다.
* 다만 **함수, 괄호, 후위 연산**을 지원하려면
  → 결국 RPN/셔닝야드 같은 “스택 기반 파서”가 더 깔끔합니다.
* 이 프로젝트는 공학용이라 함수/괄호/후위연산까지 포함해야 하니까
  → 유지보수성과 확장성을 위해 RPN 방식을 쓴 거예요.

---

👉 그래서:

* 만약 **사칙연산만** 필요한 “미니 계산기”라면 말씀한 순차 스캔 방식이 최고로 간단합니다.
* 하지만 **공학용 계산기**라면 지금처럼 **셔닝야드 + RPN**이 가장 범용적이고 안정적인 선택이에요.

---

원해요? 제가 사칙연산만 지원하는 **간단한 왼→오 스캔 평가기**를 짜서 보여드릴까요?

좋아! “셔닝야드(Shunting Yard)”와 “RPN(Reverse Polish Notation, 후위 표기)”를 **개념 → 알고리즘 → 예시 → 우리 코드와 매핑** 순서로 깔끔하게 풀어볼게.

---

# RPN(후위 표기)란?

* **표기법**: 연산자를 피연산자 뒤에 쓰는 방식.

  * 중위: `3 + 4`
  * **후위**: `3 4 +`
* **괄호가 필요 없음**: 우선순위/결합법칙을 **표기 자체**가 내포.
* **평가가 단순**: 스택 하나로 왼→오 스캔하며 처리 가능.

  1. 숫자면 push
  2. 연산자면 필요한 개수만큼 pop → 계산 → 결과 push
  3. 마지막에 스택에 값 1개가 남으면 그게 답

간단 예) `3 4 2 * 1 5 - / +`

* 흐름:

  * `3` push → `4` push → `2` push → `*` → `8` → `1` push → `5` push → `-` → `-4`
  * `/` → `8 / -4 = -2` → `+` → `3 + (-2) = 1`
* 결과: `1`

---

# 셔닝야드(Shunting Yard)란?

\*\*중위 표기(사람 친숙)\*\*를 \*\*후위 표기(계산 친숙)\*\*로 바꾸는 **알고리즘**이야.
에츠허르 다익스트라가 만들었고, 이름은 철도 분기(선로)에서 따옥.

## 핵심 아이디어

* **출력 큐(out)**: 만들어질 RPN 토큰들이 쌓이는 곳
* **연산자 스택(op stack)**: 아직 출력되지 않은 연산자/함수/왼괄호가 잠깐 머무르는 곳
* **규칙**

  * 숫자/상수 → **바로 out**
  * **후위 연산자**(²/³/% 같은 POST) → 피연산자 바로 뒤니까 **곧장 out**
  * 함수명(FUNC) → **op stack**에 push
  * 왼괄호 → **op stack**에 push
  * 오른괄호 → 왼괄호 만날 때까지 **op stack → out** pop
    (닫히자마자 스택 top이 함수면 그 함수도 **out**으로 이동: `f(x)` 형태 완성)
  * 일반 연산자 `+ - * /` → 스택 top이 **동일/더 높은 우선순위**면 계속 pop→out, 그 뒤 자기 자신 push
  * 입력이 끝나면 스택에 남은 것들을 모두 out으로 pop (괄호 남아있으면 오류)

### 우선순위/결합법칙

* 우선순위: `* /` > `+ -` (여기서는 `^` 없음)
* 결합법칙: 전부 **좌결합**(왼쪽부터 묶임).
  (만약 `^`를 넣으면 보통 **우결합**으로 취급)

# 예시 1: 기본 사칙 + 괄호

식: `3 + 4 × 2 ÷ (1 - 5)`
(내부 평가는 `×→*`, `÷→/`로 바꿔 처리)

1. 토큰: `3 NUM`, `+ OP`, `4 NUM`, `* OP`, `2 NUM`, `/ OP`, `(` LPAREN, `1 NUM`, `- OP`, `5 NUM`, `)` RPAREN
2. 셔닝야드 실행:

   * `3` → out: `3`
   * `+` → stack: `+`
   * `4` → out: `3 4`
   * `*` → stack top `+`는 우선순위 낮으므로 push → stack: `+, *`
   * `2` → out: `3 4 2`
   * `/` → stack top `*`는 우선순위 같음 → pop→out(`*`) → then push `/` → stack: `+, /`
   * `(` → push → stack: `+, /, (`
   * `1` → out: `3 4 2 * 1`
   * `-` → stack top `(`면 즉시 push → stack: `+, /, (, -`
   * `5` → out: `3 4 2 * 1 5`
   * `)` → `(`가 나올 때까지 pop→out: `-` → out: `3 4 2 * 1 5 -` → `(` 제거
     (괄호 직후 함수가 있으면 그 함수도 out로 보내지만 이번엔 없음)
   * 입력 종료 → 스택 비우기: `/`, `+` 순서로 out
3. 결과 RPN: `3 4 2 * 1 5 - / +`
4. RPN 평가는 앞에서 본 그대로 → `1`

---

# 예시 2: 함수 + 후위연산

식: `2 × sin(30)² + 5³` (Deg 모드 가정)

1. 토큰(우리 구현의 타입 기준):

   * `2 NUM`, `* OP`, `sin FUNC`, `(` LPAREN, `30 NUM`, `)` RPAREN, `² POST`, `+ OP`, `5 NUM`, `³ POST`

2. 셔닝야드:

   * `2` → out: `2`
   * `*` → stack: `*`
   * `sin` → stack: `*, sin`
   * `(` → stack: `*, sin, (`
   * `30` → out: `2 30`
   * `)` → `(`까지 pop → out: `2 30` (괄호 제거) → **직후 스택 top이 함수(sin)** → sin도 out
     out: `2 30 sin`
   * `²`(POST) → **곧장 out**: `2 30 sin ²`
   * `+` → stack: `*, +` (우선순위 비교 후 `*`를 out로 빼고 `+`를 push하는 것이 정석)
     정확히는: stack top `*`(더 높음) → pop→out: `*` → push `+` → stack: `+`
     → out: `2 30 sin ² *`
   * `5` → out: `2 30 sin ² * 5`
   * `³`(POST) → out: `2 30 sin ² * 5 ³`
   * 끝 → 스택 비우기: `+`

3. 최종 RPN: `2 30 sin ² * 5 ³ +`

4. RPN 평가(스택):

   * `2` push
   * `30` push
   * `sin` → pop `30` → (Deg면 rad로 변환 후) `sin(30°)=0.5` → push `0.5`
   * `²` → pop `0.5` → `0.25` push
   * `*` → pop `0.25`, pop `2` → `2*0.25=0.5` push
   * `5` push
   * `³` → pop `5` → `125` push
   * `+` → pop `125`, pop `0.5` → `125.5` push
   * 결과: `125.5`

# 우리 코드와의 정확한 매핑 포인트

1. **토큰 타입**

   * `('NUM', float)`, `('OP', '+-*/')`, `('LPAREN','(')`, `('RPAREN',')')`
   * `('CONST','pi'|'ans')`
   * `('FUNC', 'sin'|'cos'|'tan'|'sinh'|'cosh'|'tanh')`
   * `('POST', '²'|'³'|'%')`

2. **단항 마이너스 보정**

   * `_fix_unary_minus`: 식 시작/연산자/왼괄호/함수 뒤에 나오는 `-x` → `0 - x`로 바꿔 **항상 이항 연산**으로 처리.

3. **셔닝야드 구현** (`_to_rpn`)

   * 우선순위 `prec = {'+':1,'-':1,'*':2,'/':2}`
   * `POST`(²/³/%)는 **피연산자 다음에 바로 out** (스택에 올리지 않음)
   * `)` 처리 후, 스택 top이 `FUNC`면 **함수 토큰도 out** (f(x) 패턴)
   * 입력 종료 후 스택 정리 시 괄호가 남아 있으면 오류

4. **RPN 평가** (`_eval_rpn`)

   * `NUM` push
   * `CONST`: `ans` → `last_result`(없으면 0.0), `pi` → `math.pi`
   * `OP` → 2항 계산(+,-,\*,/)
   * `FUNC` → 1항 계산(`apply_function`) — Deg 모드면 rad 변환 포함
   * `POST` → 1항 계산(`apply_postfix`) — ²/³/%
   * 끝나고 스택에 값 1개만 있어야 유효

---

# 셔닝야드+RPN의 장점(왜 이걸 쓰나)

* **괄호, 함수, 후위 연산**이 자연스럽게 들어맞음.
* 연산자 우선순위/결합법칙을 **한 군데**(우선순위 테이블)에서 관리.
* 변환 단계와 평가 단계가 분리되어 **디버깅과 확장**이 쉬움.
* 시간복잡도 **O(n)** (토큰 각각 스택에 한번 push/pop하고 끝).

---

# “왼→오 순차 스캔” 방식과 비교

* **사칙만** 하면 순차 스캔이 더 “짧아” 보일 수 있음.
* 하지만 **괄호/함수/후위연산**이 섞이면 순차 스캔의 코드가 **빠르게 복잡**해짐:

  * 괄호 깊이 관리
  * 함수 인자 경계 처리
  * 후위 연산은 직전 피연산자 수정 필요
* 셔닝야드는 이런 복잡도를 **스택**과 **표기 변환**으로 단순화.

---

# 정리

* **RPN** = 괄호 없는 표기 + 스택 평가로 단순/안전.
* **셔닝야드** = 중위 → RPN 변환기. 우선순위/결합법칙/괄호/함수를 **일관된 규칙**으로 처리.
* 지금 프로젝트는 공학용(함수/후위/괄호 필수) → **셔닝야드+RPN**이 가장 안정적이고 유지보수도 쉬운 선택.

원하면 “이 식이 코드 안에서 토큰→RPN→평가”로 어떻게 흘러가는지 **원하는 예시**를 주면, 그 케이스를 코드 흐름대로 세부 추적해 줄게!
