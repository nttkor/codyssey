## 0) 목표 요약

* **문제 3**: PyQt6 UI의 각 버튼 이벤트를 처리해 **숫자/연산자/함수 입력이 디스플레이에 누적**되도록 구현. (= 버튼 시 결과 표시)
* **문제 4**:

  * **Calculator**(일반 계산 전용) 클래스 구현
  * 이를 상속하는 **EngineeringCalculator**(공학 기능 추가) 구현
  * 삼각/쌍곡함수(**sin, cos, tan, sinh, cosh, tanh**), **π**, **x², x³** 등 공학 기능 메서드 제공
  * **math** 외 외부 패키지 사용 금지(= `eval` 금지, 독자 파서)
  * **MC/MR/M+/M-** 구현(버튼 객체명 `btno_m_` 시작)
  * UI 버튼들과 위 기능을 **오브젝트 id 또는 텍스트**로 매핑

## 1) 아키텍처 개요

### 1.1 구성요소 (MVC 유사)

* **Model**

  * `Calculator`:

    * 숫자/사칙/괄호/Ans만으로 식을 파싱/평가.
    * 공학 확장 포인트 3개(훅): `apply_function`, `apply_postfix`, `const_value`.
    * **메모리**(MC/MR/M+/M-)와 **Ans(last\_result)** 상태 보유.
  * `EngineeringCalculator(Calculator)`:

    * 공학 기능 구현: **π**, **sin/cos/tan/sinh/cosh/tanh**, **²/³/%**.

* **View**

  * `.ui` 파일 **engineering.ui** 를 **런타임 로드**(uic.loadUi).
  * 두 디스플레이: `le_expr`(입력/표시식), `le_result`(결과).

* **Controller**

  * `MainWindow(QMainWindow)`:

    * 버튼 → 핸들러 바인딩(오브젝트 id 규칙 + 텍스트 폴백).
    * 입력 규칙(암시적 곱셈, ‘=’ 이후 Ans 시드, 괄호 자동 닫기 등).
    * 결과 표시/에러 처리/각도 모드 토글/메모리 호출.
    * **폰트 자동 축소**(19자까지 48pt, 이후 길이 비례 축소, 최소 12pt).

### 1.2 파일 구조

* `engineering_calculator.py` : 메인 실행 스크립트(모든 클래스 포함).
* `engineering.ui` : Qt Designer로 만든 UI(프로젝트 루트에 위치).

## 2) UI & 버튼 처리 정책

### 2.1 버튼 → 기능 매핑

* **오브젝트 id 규칙**

  * 숫자/소수점: `btnn_7`, `btnn_dot`
  * 공학함수: `btnf_sin`, `btnf_tanh` …
  * 일반연산/시스템: `btno_plus`, `btno_div`, `btno_open`, `btno_equal`, `btno_rad` …
  * **메모리**: `btno_m_c`, `btno_m_r`, `btno_m_plus`, `btno_m_minus`  *(문제 조건 “btno\_m\_ 시작” 충족)*
* **텍스트 폴백**

  * objectName이 예상과 다르거나 비어도 버튼 **라벨 텍스트**를 보고 기능 매핑.
  * 예: `"÷"` → 나눗셈, `"x²"` → 제곱, `"π"` → 파이, `"AC"` → 클리어.

> 장점: **UI 변경 내성**↑. objectName/텍스트 둘 중 하나만 맞아도 동작.

### 2.2 디스플레이 정책

* **표시식(le\_expr)** 에는 **곱셈 `x`**, **나눗셈 `÷`** 로 보이게 함.

  * **평가 직전** 내부식으로 변환: `x/× → *`, `÷ → /`.
* **자동 폰트 축소**:

  * 길이 ≤ 19 → 48pt
  * 길이 > 19 → `max(12, min(48, int(800/len)))`
  * `le_expr`, `le_result` 모두 **textChanged** 시 즉시 반영.

### 2.3 입력 규칙

* **숫자**: 그냥 누적. 소수점은 같은 숫자 세그먼트에 **중복 금지**.
* **연산자**: `+ - x ÷` 그대로 표시식에 누적.
* **함수**(sin/cos/tan/sinh/cosh/tanh):

  * 함수 버튼 누르면 **이름 + “(”** 삽입(즉시계산형 아님).
  * 앞이 **값**(숫자/)/π/제곱/%)이면 **암시적 곱셈**으로 `"x"` 자동 삽입.
* **괄호**:

  * 숫자 뒤에 `(` → 자동으로 `"x("`
  * `=` 시 **괄호 자동 닫기**(남은 만큼 `)` 추가).
* **%**: 숫자 뒤에서만 허용되는 **후위 연산자**. 평가 시 **× 0.01**.
* **DEL**:

  * 함수 머리(`sin(`, `cos(`, `tan(`, `sinh(`, `cosh(`, `tanh(`)는 **통삭제**(고정 접미사 비교, re 미사용).
  * `²/³/%`는 **1글자 삭제**.
  * 그 외 일반 1글자 삭제.
* **미구현/보류 기능**: **2nd, Rand, ±** → **비활성화 + 회색**(눌러도 무효).
* **inv\_mode(2nd)**: **라벨만 유지**, 동작 없음.

### 2.4 “= 이후 이어 계산(Ans)” 정책

* `=` 후 다음 입력이 **사칙연산** 또는 **x²/x³**이면:

  * 하단 결과는 **그대로 유지**,
  * `le_expr`가 비어 있으면 **자동으로 `Ans`를 시드**하고 연산자를 이어붙임.
* 다음 입력이 **함수**라면:

  * **새 식 시작**(표시/결과 클리어) 후 `함수명(` 삽입.
* `Ans x`가 이미 있는 상태에서 **함수**를 누르면 그 뒤에 그냥 이어서 삽입(곱 연산).

## 3) 계산 엔진 설계 (문제 4의 핵심)

### 3.1 `Calculator` (일반 계산 책임)

* **역할**:

  * **토큰화 → 단항 마이너스 보정 → 샌딩야드 → RPN 평가** 파이프라인 제공.
  * 사칙/괄호/숫자/상수(Ans)만 처리.
  * 공학 기능은 **훅**으로 위임.

* **핵심 메서드**

  * `evaluate_expr(s, angle_mode_rad) -> float`
    전체 파이프라인 실행.
  * `_tokenize(s) -> list[Token]`
    정규식 없이 문자 스캔으로 숫자/연산자/괄호/식별자/후위 토큰 생성.
  * `_fix_unary_minus(tokens)`
    문맥에 따라 단항 `-`를 `0 - x`로 보정.
  * `_to_rpn(tokens) -> list[Token]`
    **샌딩-야드 알고리즘**으로 중위식을 후위(RPN)로 변환.
  * `_eval_rpn(rpn, angle_mode_rad) -> float`
    RPN을 스택으로 평가.

    * **사칙연산** 직접 처리
    * `CONST('ans')` → `last_result`
    * `FUNC` → `apply_function()` **(훅 호출)**
    * `POST` → `apply_postfix()` **(훅 호출)**
    * `CONST('pi')` 등 → `const_value()` **(훅 호출)**

* **메모리 함수** (문제 요구 “mc 버튼의 역할” 대응)

  * `mem_clear()` / `mem_recall()` / `mem_add(x)` / `mem_sub(x)`
  * **MC/MR/M+/M-의 핵심 로직은 Calculator(모델)에 둔다** →
    버튼은 **MainWindow(컨트롤러)** 에서 호출만.

> **답:** **`mc`(메모리 클리어)의 실제 동작은 Calculator 클래스(모델)** 에 있어야 함. 버튼이 눌리면 MainWindow가 `engine.mem_clear()`를 호출.

### 3.2 `EngineeringCalculator(Calculator)` (공학 확장)

* **기본 각도 모드**: **Deg**(False). 버튼으로 Rad/Deg 전환.
* **훅 구현**

  * `const_value(name)`

    * `'pi'` → `math.pi`
  * `apply_function(name, x, angle_mode_rad)`

    * `sin/cos/tan` : Deg 모드면 `math.radians(x)` 후 계산
    * `sinh/cosh/tanh` : 그대로 `math` 쌍곡 함수
  * `apply_postfix(op, a)`

    * `'²'` → `a*a`
    * `'³'` → `a*a*a`
    * `'%'` → `a*0.01`

> **math 외** 외부 패키지 사용 없음 / **eval 미사용**.

## 4) MainWindow 설계 (문제 3의 핵심)

### 4.1 UI 로딩 & 위젯 참조

* `uic.loadUi("engineering.ui", self)`
* `self.le_expr`, `self.le_result` 를 objectName으로 탐색.
* `textChanged` 시그널로 **폰트 자동 축소** 연결.

### 4.2 버튼 바인딩

* 모든 `QPushButton/QToolButton`에 대해 **공통 슬롯** 바인딩: `on_button_clicked(btn)`
* **라우팅 규칙**:

  1. objectName → 접두(`btnn_`, `btnf_`, `btno_`)와 **별칭화**(`_alias`) → `do_*` 호출
  2. 실패 시 라벨 텍스트로 추정(`_key_from_text`) → `do_*`

### 4.3 주요 핸들러

* **숫자/소수점**: `_append_digit()`, `_append_dot()`
* **연산자**: `do_plus()`, `do_minus()`, `do_mul()`, `do_div()`

  * `=` 직후면 **Ans 시드**
* **함수**: `insert_function(name)` & `do_sin/cos/tan/sinh/cosh/tanh`

  * 앞이 값이면 **암시적 곱셈 x** 삽입
  * `=` 직후면 **새 식 시작**
* **상수**: `do_pi()` (필요 시 x 자동 삽입)
* **후위연산**: `do_pow2()`, `do_pow3()`, `do_percent()`
* **괄호**: `do_open()` (숫자 뒤면 `"x("`), `do_close()`
* **시스템**:

  * `do_ac()` : 표시/결과/상태 초기화
  * `do_del()` : 함수머리 통삭제 / ²·³·% 1글자 삭제 / 일반 1글자 삭제
  * `do_equal()` :

    * **표시식 → 내부식** 변환(`x/×/÷` ↦ `*/`)
    * **괄호 자동 닫기**
    * `engine.evaluate_expr()` 호출
    * 결과(`le_result`) & **Ans 갱신**, `_pending_clear=True` 설정
* **각도모드**: `do_rad()` (라벨 ‘Rad/Deg’ 토글)
* **메모리**:

  * `do_m_c()`: `engine.mem_clear()`
  * `do_m_r()`: 메모리값을 **표시식에 삽입**(필요 시 x)
  * `do_m_plus()`, `do_m_minus()`:

    * 우선 **결과창** 숫자, 없으면 **표시식 평가**, 실패 시 무시

## 5) 예외/에러 처리

* **평가 실패**(파싱/연산 오류 등) → 결과창에 `"Error"` 표시, Ans는 `None`.
* **DEL의 함수머리 삭제**는 **고정 접미사 비교**로 구현(요구대로 **re 미사용**).

## 6) 표시 포맷(유효숫자/소수점)

* `fmt_number()` 에서 **정수는 정수로**, 그 외는

  * `FIXED_DECIMALS` 설정 시 **고정 소수점**
  * 아니면 **유효숫자 `SIG_DIGITS`** (기본 12, 필요 시 15\~16까지 추천)
* 폰트 자동 축소로 긴 숫자도 표시 안정.

## 7) 확장 가이드

* 새 함수 추가:

  * UI에 버튼 추가(`btnf_xxx`) → `ENABLED_FUNCS`에 키 추가 →
  * `EngineeringCalculator.apply_function()`에서 `elif n == 'xxx'` 분기 구현.
* 새 후위 연산자:

  * 토크나이저에서 기호 추가 → `apply_postfix()` 구현 → DEL 규칙 보강.
* 상수 추가:

  * 토크나이저(문자/식별자)에서 이름 인식 → `const_value()`에 이름 매핑.

## 8) 테스트 체크리스트

1. **사칙/괄호/소수점** 기본 동작
2. **함수 입력 시 암시적 곱셈**(숫자 뒤 `x` 자동)
3. **%**(숫자 뒤에서만), **²/³** 후위
4. `=` 이후 **Ans 시드** 규칙(사칙/제곱 vs 함수)
5. **DEL**: 함수머리 통삭제 / ²·³·% 1글자 삭제
6. **Rad/Deg**: `sin(30)`(Deg)와 `sin(π/6)`(Rad) 결과 비교
7. **메모리**: MR/M+/M-/MC 순서
8. **폰트 자동 축소**: 19자 경계 및 초과 길이
9. **표시식 ↦ 내부식 변환**: `x`/`×`/`÷` 처리
10. **괄호 자동 닫기**: `((2+3` → `((2+3))` 평가 정상

## 10) “mc 버튼은 어느 클래스에 넣어야 할까” 최종 답변

* **상태(메모리 값)와 연산 로직은 `Calculator`(모델)에 둔다.**

  * 즉, `mem_clear()`, `mem_recall()`, `mem_add()`, `mem_sub()` 는 **Calculator**에 구현.
* **버튼 이벤트 핸들러는 `MainWindow`(컨트롤러)** 에서 처리해 **모델 메서드를 호출**한다.

  * 예: `do_m_c()` → `self.engine.mem_clear()` 호출.

이렇게 하면 **응집도**가 높고(계산 상태는 모델 내부), **UI 교체에도 강함**(버튼 배치/라벨이 바뀌어도 로직은 영향 적음).

# 2) 사칙/괄호/일반 연산

| 연산        | objectName 패턴(예) | 라벨 텍스트 폴백                      | 내부 핸들러       | 특이사항                                    |
| --------- | ---------------- | ------------------------------ | ------------ | --------------------------------------- |
| 더하기       | `btno_plus`      | `"+"`, `"add"`                 | `do_plus()`  | `=` 직후면 `Ans+`로 시드                      |
| 빼기        | `btno_minus`     | `"-"`, `"sub"`                 | `do_minus()` | 同上                                      |
| 곱하기(표시 x) | `btno_mul`       | `"*"`, `"x"`, `"×"`, `"times"` | `do_mul()`   | 표시는 `x`, 평가 전 `*`로 변환. `=` 직후 `Ansx` 시드 |
| 나누기(표시 ÷) | `btno_div`       | `"/"`, `"÷"`, `"divide"`       | `do_div()`   | 표시는 `÷`, 평가 전 `/`로 변환. `=` 직후 `Ans÷` 시드 |
| 여는 괄호     | `btno_open`      | `"("`                          | `do_open()`  | 숫자 뒤면 자동으로 `x(`                         |
| 닫는 괄호     | `btno_close`     | `")"`                          | `do_close()` | 그대로 `)` 추가                              |

> 평가 직전에 **표시식 → 내부식** 변환: `x/× → *`, `÷ → /`

# 3) 공학 함수/상수

| 기능   | objectName 패턴(예) | 라벨 텍스트 폴백     | 내부 핸들러      | 특이사항                       |
| ---- | ---------------- | ------------- | ----------- | -------------------------- |
| sin  | `btnf_sin`       | `"sin"`       | `do_sin()`  | 앞이 값이면 암시적 곱(`x`) 후 `sin(` |
| cos  | `btnf_cos`       | `"cos"`       | `do_cos()`  | 同上                         |
| tan  | `btnf_tan`       | `"tan"`       | `do_tan()`  | 同上                         |
| sinh | `btnf_sinh`      | `"sinh"`      | `do_sinh()` | 同上                         |
| cosh | `btnf_cosh`      | `"cosh"`      | `do_cosh()` | 同上                         |
| tanh | `btnf_tanh`      | `"tanh"`      | `do_tanh()` | 同上                         |
| π    | `btnf_pi`        | `"π"`, `"pi"` | `do_pi()`   | 앞이 값이면 `xπ` (암시적 곱)        |

> **함수 입력은 즉시계산 아님**: `이름+“(”` 형태로 누적.
> **‘=’ 직후 함수** → 새 식 시작(표시/결과 클리어 후 `함수명(` 삽입). 단, 이미 `Ans x` 상태라면 그대로 이어 붙음.

# 6) 메모리(버튼 id는 **btno\_m\_** 시작)

| 기능 | objectName 패턴(예) | 라벨 텍스트 폴백        | 내부 핸들러         | 동작(모델: Calculator)                    |
| -- | ---------------- | ---------------- | -------------- | ------------------------------------- |
| MC | `btno_m_c`       | `"mc"`           | `do_m_c()`     | `mem_clear()` – 메모리 0                 |
| MR | `btno_m_r`       | `"mr"`           | `do_m_r()`     | 메모리값을 `le_expr`에 숫자로 삽입(필요시 `x` 덧붙임)  |

# 8) 평가·파싱 관련(참고)

| 표시 토큰     | 내부 토큰             | 비고                           |
| --------- | ----------------- | ---------------------------- |
| 숫자/소수     | `NUM`             | `.` 중복 방지                    |
| `+ - x ÷` | `OP(+, -, *, /)`  | `x/× → *`, `÷ → /` 변환은 평가 직전 |
| `(` `)`   | `LPAREN` `RPAREN` | `=` 시 자동 괄호 닫기               |
| `sin(` 등  | `FUNC(sin)`       | 닫는 괄호 시 함수 pop               |
| `π`, `pi` | `CONST(pi)`       | `math.pi`                    |
| `Ans`     | `CONST(ans)`      | 마지막 결과                       |
| `² ³ %`   | `POST(²/³/%)`     | 후위 연산                        |

## 사용 팁

* UI에서 새 버튼을 추가할 땐 **objectName 규칙**을 지키면 자동 인식돼.
  예) `btnf_log` 추가 후 `ENABLED_FUNCS` & `EngineeringCalculator.apply_function`에 구현만 넣으면 됨.
* 라벨만 넣어도 동작하도록 **텍스트 폴백**이 준비되어 있어, 빠르게 시험해볼 수 있어.

필요하면 이 표를 **제출용 PDF**로 꾸며주거나, 현재 **engineering.ui**의 실제 버튼 목록을 읽어 **실물 매핑표**로 더 구체화해 줄 수도 있어!
