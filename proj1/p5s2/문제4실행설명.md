(설명은 너에게 준 주석 많은 버전의 `calculator4.py`와 1:1로 대응돼.)

# 0. 파이썬이 파일을 읽기 시작할 때

   * **PyQt6** 주요 구성요소 로드:

     * `uic`(런타임에 `.ui` 로드)
     * `QApplication, QMainWindow, QPushButton, QLineEdit`(핵심 위젯)
     * `Qt`(정렬 등 상수), `QFont`(폰트 조절)
   * `from engineering_calculator import EngineeringCalculator`
     → 공학 계산 엔진 클래스 정의를 메모리에 올림(여기선 **정의만**, 생성은 나중에)

2. **함수/클래스 정의만 등록**

   * `find_ui_path()` 유틸 함수 정의
   * `UIWindow(QMainWindow)` 정의(로드된 창 래퍼)
   * `MainWindow` 정의(통합 컨트롤러)
   * 아직 **어떤 것도 실행되지 않았음**(선언만 된 상태)

# 1. 엔트리포인트 진입

3. `if __name__ == "__main__":` 블록 실행

   * `app = QApplication(sys.argv)`
     → **Qt 애플리케이션 객체** 생성(이벤트 루프는 아직 시작 전)
   * `mw = MainWindow()`
     → 이제부터 **우리 앱 초기화의 핵심 단계**가 순서대로 실행됨
   * `sys.exit(app.exec())`
     → 마지막에 **이벤트 루프 진입**(런타임 상호작용이 여기서 시작)

# 2. `MainWindow.__init__` (앱 초기화 핵심)

4. **공학 엔진 인스턴스 생성**

   * `self.calc = EngineeringCalculator()`
     → 삼각/쌍곡/제곱/세제곱/π/로그/루트/멱/메모리/각도모드 등 **실제 계산 로직**을 제공

5. **상태 변수 초기화**

   * `expression_str=""` (표시용 문자열 버퍼—필요시 사용)
   * `op1=None`, `operator=None`, `awaiting_second=False`
     → **이항 연산**(예: `x^y`)을 위해 첫 피연산자/연산자/대기 상태를 보관

6. **UI 두 개 로드**

   * `self.win_engineering = UIWindow(find_ui_path("engineering.ui"))`
   * `self.win_basic = UIWindow(find_ui_path("caculator.ui"))`
   * 여기서 먼저 `find_ui_path()`가 호출되어 **경로 탐색**:

     * 탐색 순서: `파일과 같은 폴더` → `현재 작업폴더` → `/mnt/data`
     * 찾으면 문자열 경로를 반환, 못 찾으면 **즉시 예외**로 중단
   * `UIWindow.__init__` 내부 동작(각 UI마다 동일):

     1. `uic.loadUi(ui_path, self)`로 **.ui를 런타임 로드** → 이 인스턴스(QMainWindow)에 위젯 트리 생성
     2. `led` 찾기: objectName이 `'led'`면 사용, 아니면 첫 `QLineEdit` 채택
     3. `led` 속성 설정:

        * `setReadOnly(True)` → 사용자 타이핑 방지
        * `setAlignment(Qt.AlignRight|AlignVCenter)` → 계산기처럼 **우측 정렬**
     4. 창 내부의 **모든 `QPushButton`를 수집** → 이후 자동 배선에 사용

7. **현재 창/상대 창 포인터 설정**

   * `self.current = self.win_engineering`(기본은 공학형)
   * `self.other = self.win_basic`

8. **초기 디스플레이**

   * `_apply_display("0")` 호출

     * `led.setText("0")`
     * `_fit_font("0")` → 길이에 따라 **폰트 크기 동적 조절**(≤10글자: 48pt, 그 이상: 480/글자수, 최소 12pt)

9. **버튼 자동 배선**

   * `_wire_window(self.win_engineering)` → 공학형 창의 **모든 버튼**을 순회하며 연결
   * `_wire_window(self.win_basic)` → 기본형 창도 **동일 로직**으로 연결
   * `_wire_window()` 내부 동작(버튼 하나마다):

     1. 버튼 `objectName`/`text()` 가져오기
     2. `text()`를 **정규화**: `_normalize_label(raw_label)`

        * 예: `×/X/* → *`, `x²/x^2 → x^2`, `π/pi → π`, `log/log₁₀ → log10`, `⌫/back → ⌫`, `AC/C/CE → AC`, …
     3. **분기 연결(시그널-슬롯)**:

        * `AC/C/CE` → `_on_ac`
        * `=` → `_on_equals`
        * `⌫` → `_on_backspace`
        * `MC/MR/M+/M-/MS` → `_on_memory(key)`
        * `DEG/RAD` → `_on_angle_mode(label)`
        * `±` → `_on_negate`
        * `%` → `_on_percent`
        * `x^y`(이항) → `_on_binary_op("POW")`
        * 그 외 **모든 버튼** → `_on_generic_input(label, objectName)`

     * 연결 시 **lambda 기본 인수**로 현재 라벨을 캡처(`t=label`)
       → 루프 끝난 뒤에도 각 버튼이 **자기 라벨**을 정확히 유지(지연 바인딩 버그 회피)

10. **Mode 버튼 연결**

    * `_connect_mode_button(win_engineering)` / `_connect_mode_button(win_basic)`
    * 각 창에서 **Mode 버튼**을 찾아 `clicked → toggle_mode`에 연결

11. **초기 창 표시**

    * `self.current.show()` → **공학형 창 표시**

# 3. 이벤트 루프 시작 후(런타임 상호작용)

12. `app.exec()`로 **Qt 이벤트 루프 진입**

    * 이제부터는 **사용자 입력(클릭/키보드)**, **리페인트**, **타이머** 등이 이벤트로 처리

---

## A. “단항 함수” 버튼을 눌렀을 때 (예: `sin`, `cos`, `tan`, `sinh`, `cosh`, `tanh`, `x^2`, `x^3`, `π`)

1. 사용자가 버튼 클릭 → Qt가 해당 버튼의 **`clicked` 시그널** emit
2. `_wire_window()`에서 연결해둔 **슬롯** 실행:

   * 대부분은 `_on_generic_input(label, objectName)`
3. `_on_generic_input` 내부 흐름

   * 인자로 들어온 `label`은 이미 **정규화**된 표기(예: `x²` → `x^2`)
   * `unary_map`에서 **단항/상수**에 매칭되는지 확인

     * 예: `"sin" → self.calc.sin(x)"`, `"x^2" → self.calc.square(x)"`, `"π" → self.calc.const_pi()"`
   * **현재 표시값**을 읽기: `_get_display_value()`

     * `led.text()`를 가져와 `float()` 파싱
     * `"π"`이면 `math.pi`로 대체
     * 숫자 외 문자가 섞이면 **정규식으로 첫 숫자 토큰만 추출**해 파싱 시도
     * 실패 시 `0.0`
   * **엔진 호출**:

     * 상수(π/e)처럼 **인자 없는 함수**는 그대로 호출
     * 일반 단항은 `fn(cur)`로 호출
     * 내부에서 **정의역/범위/분모 0/무한대** 등 검사(오류 시 `ValueError` 발생)
   * 결과 표시: `_show_result(res)`

     * 거의 0인 값은 0.0으로 스냅
     * `"{:.12g}"` 포맷으로 **12 유효자리** 표시(과학 표기 허용)
     * `_apply_display`가 폰트 자동 조절까지 수행
   * 예외 발생 시 `_show_error()`로 **"Error"** 표시

> 예: `DEG` 모드에서 `cos(90)` → 내부에서 라디안 변환 후 오차를 0으로 스냅 → `0`

---

## B. “이항 연산” 흐름 (예: `x^y` → `=`)

1. 사용자가 `x^y` 버튼 클릭

   * `_wire_window()`에서 `label == "x^y"`인 경우 `clicked → _on_binary_op("POW")`
2. `_on_binary_op("POW")`

   * `op1 = _get_display_value()`로 **첫 피연산자 저장**
   * `operator = "POW"`, `awaiting_second = True`
   * 디스플레이를 `"0"`으로 초기화(두 번째 입력 받을 준비)
3. 사용자가 두 번째 숫자를 입력

   * `_on_generic_input`에서 `awaiting_second`가 True면 **표시를 지우고** 새 입력부터 누적
4. 사용자가 `=` 클릭

   * `_on_equals()` 실행
   * `operator`가 `"POW"`인지 확인 → `cur = _get_display_value()`로 **두 번째 피연산자** 획득
   * `res = self.calc.pow_xy(op1, cur)` 호출

     * 엔진에서 `math.pow` 기반 계산 + **도메인/범위 검사**
   * `_show_result(res)`로 표시
   * **체인 연산** 대비: `op1 = res`, `operator=None`, `awaiting_second=False`
   * **오류 발생** 시 `_show_error()` 및 상태 초기화

---

## C. 메모리 키 (MC / MR / M+ / M- / MS)

1. 사용자가 `MC/MR/M+/M-/MS` 클릭

   * `_wire_window()`에서 `clicked → _on_memory(key)`
2. `_on_memory(key)`

   * `MC`: `self.calc.memory_clear()`
   * `MR`: `v = self.calc.memory_recall()` → `_show_result(v)`로 **표시값으로 주입**
   * `M+`: `self.calc.memory_add(현재표시값)`
   * `M-`: `self.calc.memory_sub(현재표시값)`
   * `MS`: `self.calc.memory_store(현재표시값)`
   * 예외 시 `_show_error()`

> 메모리는 \*\*연산 스택(op1/op2)\*\*와 독립. MR은 **현재 입력처럼** 작동.

---

## D. 각도 모드 (DEG / RAD)

1. 버튼을 누르면 `clicked → _on_angle_mode(label)`
2. `_on_angle_mode`

   * `self.calc.set_angle_mode("DEG"|"RAD")`
     → 이후의 `sin/cos/tan` 등은 이 모드에 맞게 **라디안 변환** 처리
3. 별도 표시/배지는 UI에 따라 다르지만, 로직은 **상태만 교체**

---

## E. 기타 특수 동작

* **AC/C/CE** → `_on_ac()`

  * 모든 상태(op1/operator/대기 플래그/버퍼) 초기화 + `"0"` 표시
* **⌫(Backspace)** → `_on_backspace()`

  * led 끝 문자 **한 글자 삭제**(문자 단위)
* **±** → `_on_negate()`

  * 표시값 **부호 반전** 후 즉시 표시
* **%** → `_on_percent()`

  * 표시값을 **100으로 나눔**(간단 비율 처리)
* **일반 입력(숫자/연산자/괄호 등)** → `_on_generic_input()`

  * 단항/상수에 해당하지 않으면 **그대로 문자열 누적**해서 표시
  * 단, `s == "0"` 또는 `'Error'` 또는 `awaiting_second`라면 **지우고** 새 입력부터 시작

---

## F. Mode(화면 전환)

1. 사용자가 **Mode 버튼** 클릭 → `clicked → toggle_mode()`
2. `toggle_mode()`

   * `self.current.hide()`로 **현재 창 숨김**
   * `self.current, self.other = self.other, self.current`로 **포인터 스왑**
   * 이전 창의 led 텍스트를 새 창으로 복사해 **표시 동기화**
   * `self.current.show()`로 **새 창을 표시**, `activateWindow()`로 포커스

> UI 파일은 **전혀 수정하지 않고**, **show/hide 전환**만 한다.

---

# 4. 디스플레이/폰트/파싱 디테일

* **폰트 조절**: `_fit_font(text)`가 **매번** 호출되어 길이에 따라 동적으로 사이즈 변경(최소 12pt)
* **파싱**: `_get_display_value()`는 다음을 순서대로 시도

  1. `float(led.text())` (직접 파싱)
  2. `"π"` 특별 처리 → `math.pi`
  3. 정규식으로 숫자 토큰 추출(문자가 섞였을 때)
  4. 실패 시 `0.0`
* **표시 포맷**: `_show_result()`에서 **소수/과학 표기 자동**(`.12g`) + **거의 0 → 0.0**

# 핵심 체크포인트 요약

* **로드 단계**: `.ui` 두 개를 `uic.loadUi`로 메모리에 동시에 올림 → **show/hide 전환**
* **버튼 배선**: 한 번 순회하며 **정규화 라벨**로 분기 → 특수/이항/단항/일반 입력 핸들러 연결
* **단항**은 **즉시 계산 표시**, **이항**은 `op1/operator/awaiting_second` → `=`에서 평가
* **오류**는 엔진에서 `ValueError(...)`로 통일 → UI `"Error"`
* **메모리/각도 모드**는 **엔진 상태**를 그대로 사용
* **폰트/표시/파싱**은 모든 표시 변경 때마다 **일관 처리**

이 흐름대로 보면, 어느 버튼을 눌러도 **어느 핸들러가 호출되고 어떤 상태가 바뀌는지**가 정확히 추적될 거야.
특정 버튼의 실제 `objectName`/라벨이 궁금하면 알려줘—정규화/매핑에 바로 반영해서 더 안전하게 만들 수 있어.
