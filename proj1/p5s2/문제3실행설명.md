# 📌 실행 순서 요약

## 1. 시작 단계

1. **모듈 import → 클래스/함수 정의**
2. `if __name__ == "__main__":` 진입
3. `QApplication` 생성
4. `AppController()` 생성 시작

---

## 2. `AppController` 초기화 순서

1. **버퍼 초기화**: `expression_buffer = ""`
2. **UI 로드**

   * `engineering.ui`, `caculator.ui` 각각 `UIWindow`로 불러옴
   * `led` 찾고 읽기전용/우측정렬 세팅
   * 모든 버튼 목록 확보
3. **현재 창 = engineering**, 다른 창 = basic
4. **디스플레이 초기값 `"0"` 적용 + 폰트 크기 조정**
5. **버튼 신호 연결**

   * AC → `on_ac`, Backspace → `on_backspace`, `=` → `on_equal`, Mode → `toggle_mode`
   * 나머지는 토큰 변환 후 `on_token`
6. **engineering 창 show()**
7. **Qt 이벤트 루프 시작 (`app.exec()`)**

---

## 3. 런타임 동작

* **일반 버튼**: `_token_from_button`으로 토큰 결정 → 버퍼에 추가 → led 표시
* **AC**: 버퍼 초기화, led `"0"`
* **Backspace**: 마지막 글자 삭제 (비면 `"0"`)
* **=**: 계산 없이 `"="`만 버퍼에 추가
* **Mode**: 현재 창 hide → 다른 창 show → led에 버퍼 그대로 반영

---

## 4. 종료

* 창 닫기 → 이벤트 루프 종료 → 프로그램 끝

---

# 0) 파일이 실행되기 시작하면 (최상단 → 하단 순서)

1. **파이썬 인터프리터가 소스코드를 위에서 아래로 읽음**

   * `import sys, os, re`, `from pathlib import Path`, `from PyQt6 ...` 등 **모듈 import**를 먼저 수행합니다.
   * 그 다음에 **함수 정의**(`find_ui_path`)와 **클래스 정의**(`UIWindow`, `AppController`)의 본문을 “실행”해서 전역 심볼 테이블에 등록합니다.

     > 주의: 함수/메서드 내용은 ‘정의’만 되고 **호출되진 않습니다**. 실제 호출은 나중에 일어납니다.

2. **`if __name__ == "__main__":` 가드**에 도달

   * 이 파일을 “직접 실행”했다면 `__name__ == "__main__"` 이므로, **블록 안의 코드가 실행**됩니다.

3. **`QApplication` 인스턴스 생성**

   ```python
   app = QApplication(sys.argv)
   ```

   * Qt 앱의 **이벤트 루프**를 돌릴 준비를 합니다. (아직 루프 시작은 아님)

4. **`AppController()` 인스턴스 생성 → `__init__` 진입**

   ```python
   ctrl = AppController()
   ```

   * 이제부터는 **컨트롤러 초기화 과정**이 상세히 진행됩니다.

# 1) `AppController.__init__` 내부에서 일어나는 일 (초기화 전체 순서)

> 이 구간이 실제로 화면을 구성하고, 버튼 신호를 연결하고, 첫 창을 띄우는 핵심입니다.

1. **표시 버퍼 초기화**

   ```python
   self.expression_buffer = ""
   ```

   * 모든 입력을 누적해서 보여줄 **문자열 버퍼**입니다.

2. **UI 경로 탐색 (engineering.ui, caculator.ui)**

   ```python
   self.ui_engineering = UIWindow(find_ui_path("engineering.ui"))
   self.ui_basic = UIWindow(find_ui_path("caculator.ui"))
   ```

   * 각 줄에서 먼저 `find_ui_path(name)`가 호출됩니다.

   ### 2-1) `find_ui_path(name)` 호출 흐름

   * 인자로 들어온 파일명(예: `"engineering.ui"`)을 **아래 순서로 찾습니다**:

     1. `Path(__file__).parent / name` → 스크립트 파일이 있는 폴더
     2. `Path(os.getcwd()) / name` → 현재 작업 디렉토리
     3. `Path("/mnt/data") / name` → `/mnt/data` (업로드 파일 폴더)
   * 이 순서로 존재 확인 후 **첫 번째로 발견되는 경로**를 반환합니다.
     찾지 못하면 `FileNotFoundError`를 발생시켜 **초기화 단계에서 바로 예외로 종료**됩니다.

3. **`UIWindow(ui_path)` 생성자 실행 (각 UI마다 1회씩)**

   * `uic.loadUi(ui_path, self)`로 **.ui 파일을 로드**하고, 해당 UI에 정의된 모든 위젯들을 이 QMainWindow(`self`) 인스턴스 안에 생성·배치합니다.
   * `self.ui_path = ui_path` 저장.
   * **led 찾기**:

     ```python
     self.led = getattr(self, "led", None)
     if self.led is None:
         qles = self.findChildren(QLineEdit)
         self.led = qles[0] if qles else None
     ```

     * 우선 objectName이 `"led"`인 속성을 직통으로 찾고, 없으면 첫 번째 `QLineEdit`를 led로 사용합니다.
   * **led 기본 속성 적용**:

     ```python
     self.led.setReadOnly(True)
     self.led.setAlignment(Qt.AlignRight | Qt.AlignVCenter)
     ```

     * 사용자가 키보드로 led를 직접 수정하지 못하게 하고, **오른쪽 정렬**로 셋업합니다.
   * **모든 버튼 수집**:

     ```python
     self.all_buttons = self.findChildren(QPushButton)
     ```

     * 이 창에 존재하는 모든 `QPushButton` 목록을 확보합니다.
   * (`UIWindow` 생성자는 화면을 \*\*표시(show)\*\*하지 않습니다. 단지 로드·준비만 끝냅니다.)

4. **현재/반대 창 포인터 설정 + 초기 표시**

   ```python
   self.current = self.ui_engineering  # 기본 모드: 공학형
   self.other = self.ui_basic
   self._apply_display("0")
   ```

   * 기본값으로 **공학형 창**을 “현재 창”으로 설정합니다.
   * `_apply_display("0")` 호출로 **현재 창의 led에 "0" 표시** 및 폰트 스케일 적용을 합니다.

   ### 4-1) `_apply_display(text)` 호출 흐름

   * `self.current.led.setText(text or "0")`로 문자열을 넣고
   * `_fit_font(text)`로 글자 수에 따른 **동적 폰트 크기 조정**:

     * 길이 ≤ 10: **48pt**
     * 길이 > 10: `int(480 / length)` 를 계산해 **최소 12pt 보장** 후 적용
     * `QFont().setBold(True)`로 볼드도 적용

5. **버튼 신호 연결 (두 창 모두)**

   ```python
   self._wire_window(self.ui_engineering)
   self._wire_window(self.ui_basic)
   ```

   * 각 창의 `all_buttons`를 **하나씩 순회**하면서 아래 규칙으로 **clicked → 슬롯**을 연결합니다.

   ### 5-1) `_wire_window(window)` 내부 순서

   * 각 버튼에 대해 `name = objectName.lower()`, `text = b.text().strip()`을 구합니다.
   * **Mode 버튼 제외**:
     objectName이 `'btn_mode'` 이거나 텍스트에 `"mode"`가 포함된 버튼은 **여기서 건너뜁니다**. (모드는 전용 연결이 따로 있음)
   * **특수키 분기**(우선순위가 높음):

     * **AC/C/CE**: `on_ac`에 연결
     * **Backspace(⌫/Back/Backspace 또는 objectName에 'back')**: `on_backspace`에 연결
     * **= (또는 objectName 끝이 'equals')**: `on_equal`에 연결
   * **그 외 일반 키**:

     1. 먼저 `_token_from_button(text, name)`로 **버퍼에 붙일 토큰**을 계산
     2. **토큰이 `None`이 아니면**

        ```python
        b.clicked.connect(lambda _=False, t=token: self.on_token(t))
        ```

        * 여기서 **기본인자 `t=token`** 으로 캡처합니다.
          (중요: 이 방식은 루프 변수 지연 바인딩 문제를 방지해서, **각 버튼이 자기 토큰을 정확히 유지**합니다.)
     3. **토큰이 `None`이면**

        * **“매핑 실패”로 간주**하고 버튼의 **라벨 텍스트 그대로**를 다시 토큰으로 삼아 `on_token(text)`에 연결합니다.

   > ※ 결과적으로, 신호 연결이 끝나면 **두 창의 모든 버튼**이 컨트롤러의 핸들러에 연결되어 있습니다.
   > 숨겨진 창의 버튼은 화면에 보이지 않아 클릭할 수 없지만, 전환 후에는 곧바로 사용됩니다.

6. **모드 버튼 전용 연결 (두 창 모두)**

   ```python
   self._connect_mode_button(self.ui_engineering)
   self._connect_mode_button(self.ui_basic)
   ```

   * 내부에서 `find_mode_button()`을 불러 **objectName이 `btn_mode`** 인 버튼(또는 텍스트에 `"mode"`)을 찾아
     `btn.clicked.connect(self.toggle_mode)`로 연결합니다.

7. **기본 창을 화면에 표시**

   ```python
   self.ui_engineering.show()
   ```

   * 여기서 **처음으로 실제 윈도우가 뜹니다**.
   * led에는 이미 4단계에서 설정한 `"0"`이 보입니다.

8. **컨트롤러 초기화 완료 → `__init__` 종료 → `AppController()` 생성 완료**

9. **Qt 이벤트 루프 시작**

   ```python
   sys.exit(app.exec())
   ```

   * 이제부터는 **이벤트 기반**으로 동작합니다.
     키보드/마우스 입력, 리페인트, 타이머 등 **모든 상호작용은 이벤트 루프**가 처리합니다.

# 2) 런타임 동안(사용자 클릭 시) 동작 순서

## 2-1) 일반 버튼(숫자/연산/함수 등)을 클릭했을 때

1. Qt가 해당 버튼의 **`clicked` 신호**를 발생
2. 신호가 이전에 연결해 둔 **슬롯**(대개 `on_token(...)`)으로 전달
3. **`on_token(token)` 실행**

   ```python
   self.expression_buffer += token
   self._apply_display(self.expression_buffer)
   ```

   * 버퍼에 토큰을 **이어붙이고**, led에 **그대로 표시**합니다.
   * `_apply_display`는 다시 `_fit_font`를 호출하여 **글자 수에 맞게 폰트를 재조정**합니다.
4. 함수형 버튼(예: `sin`)은 `_wire_window` 시점에 `_token_from_button`이 **`"sin("`** 으로 변환해 두었기 때문에,
   클릭하면 버퍼에 실제로는 `"sin("`이 들어갑니다.

### `_token_from_button(text, object_name)` 내부 규칙(요약)

* **정확 매핑(`_exact_map`)** 우선:

  * 예: `"x²" → "^2"`, `"x³" → "^3"`, `"x! → !"`, `"1/x" → "1/("`, `"√x" → "√("` 등
  * 곱셈 라벨이 `"×"`면 `"×"`, `"X"`면 `"X"` 그대로
* **단일 기본 문자**(숫자/`. + - / * ( ) %`)는 **문자 그대로**
* **함수형**(`sin`, `cos`, `tan`, `sinh`, `cosh`, `tanh`, `ln`, `log`, `log10`, `rand`, `abs`, `asin`, `acos`, `atan`)은 **자동으로 `"함수명("`** 으로 변환

  * `log₁₀` 같은 라벨은 먼저 `log10`으로 정규화합니다.
* **`deg/rad`** 라벨은 내부에서 **토큰을 `None`으로 돌려** “버퍼에 넣지 않도록” 의도했지만,
  현재 구현은 **토큰이 `None`이면 라벨 텍스트를 그대로 넣는** 폴백이 있어서 **실제로는 버퍼에 붙습니다**.

  > (즉, 지금 버전은 `DEG/RAD`도 버퍼에 들어갈 수 있습니다. “버퍼 오염 방지”를 원하면 이 폴백 분기를 바꿔야 합니다.)

## 2-2) `AC`(Clear) 버튼을 클릭했을 때

1. `clicked → on_ac` 연결을 통해 `on_ac()` 실행
2. 내부에서

   ```python
   self.expression_buffer = ""
   self._apply_display("0")
   ```

   * 버퍼를 비우고, led에 **"0"** 표시 + 폰트 재조정

## 2-3) `Backspace(⌫)` 버튼을 클릭했을 때

1. `clicked → on_backspace` 연결을 통해 `on_backspace()` 실행
2. 내부에서

   ```python
   if self.expression_buffer:
       self.expression_buffer = self.expression_buffer[:-1]
   self._apply_display(self.expression_buffer if self.expression_buffer else "0")
   ```

   * 버퍼의 **마지막 문자 1개**를 잘라내고, 결과가 빈 문자열이면 \*\*"0"\*\*을 표시합니다.
   * (현재는 **문자 단위** 삭제입니다. `sin(`을 한 번에 지우는 “토큰 단위 삭제”는 추후 개선 포인트입니다.)

## 2-4) `=` 버튼을 클릭했을 때

1. `clicked → on_equal` 연결을 통해 `on_equal()` 실행
2. 내부에서

   ```python
   self.expression_buffer += "="
   self._apply_display(self.expression_buffer)
   ```

   * 계산은 전혀 하지 않고, **문자 `'='`만 버퍼에 추가**하여 표시합니다.

## 2-5) `Mode` 버튼을 클릭했을 때 (UI 교체)

1. 두 창의 모드 버튼 모두 `clicked → toggle_mode`로 연결되어 있음
2. **`toggle_mode()` 실행 순서**

   ```python
   self.current.hide()               # 현재 보이는 창 숨김
   self.current, self.other = self.other, self.current  # 포인터 스왑
   self._apply_display(self.expression_buffer or "0")   # 새 창의 led에 버퍼 반영
   self.current.show()               # 새 창 표시
   self.current.activateWindow()     # 포커스 줌
   ```

   * **버퍼 내용은 그대로 유지**됩니다.
   * 창만 바뀌고, 새 창의 `led`에 현재 버퍼가 바로 반영됩니다.
   * 폰트 스케일도 `_apply_display`에서 **새 창 기준으로 재계산**됩니다.

# 3) 이벤트 루프와 종료

* 앱이 실행되는 동안은 `app.exec()`의 이벤트 루프가 **계속 돌면서** 마우스 클릭, 키 입력, 리페인트 등 **모든 이벤트를 분배**합니다.
* 사용자가 창을 닫으면 `QApplication`이 **정상 종료 코드**를 반환하고,
  `sys.exit(...)`가 그 코드를 프로세스의 종료 코드로 전달하며 프로그램이 **완전히 종료**됩니다.

---

# 4) 정리 포인트(핵심 흐름만 압축)

1. **import/정의** → `QApplication` 생성 → **`AppController()` 생성**
2. 컨트롤러 초기화:

   * `engineering.ui` / `caculator.ui` 로드 → led/버튼 수집
   * 현재 창 = engineering, **"0" 표시**
   * **모든 버튼 신호 연결**
   * **Mode 버튼**은 전용으로 `toggle_mode`에 연결
   * **engineering 창 show()**
3. **이벤트 루프 시작**
4. 클릭 시:

   * 일반 키 → `_token_from_button`으로 토큰 결정 → **버퍼 += 토큰** → led 반영
   * AC/Backspace/=/Mode는 **전용 핸들러** 수행
5. **Mode** 클릭 시 **두 창 show/hide 전환**, 버퍼 표시 유지
