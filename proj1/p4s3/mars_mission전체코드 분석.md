# 📌 코드 구조 분석

## 1. **responsive\_sleep()**

* `time.sleep()`을 대체하는 함수.
* 장점:

  * 일반적으로 `sleep(5)`를 하면 **5초 동안 완전히 블록(block)** 되지만,
  * 여기서는 `interval=0.5`로 잘라서 반복 sleep → 중간에 `stop_event`가 set되면 즉시 break 가능.
* 즉, **사용자가 `q` 입력 → 중간 대기라도 바로 멈춤** 가능.

---

## 2. **DummySensor 클래스**

* 문제 1 과제 구현.
* 화성 기지의 환경값을 **랜덤 생성**:

  * 내부/외부 온도
  * 습도
  * 외부 광량
  * 내부 CO₂, 산소 농도
* `get_env()` 호출 시:

  * 현재 값을 반환
  * 동시에 `sensor_log.txt`에 `timestamp + 값들` 저장
  * → **실시간 로그 기록 및 모니터링 가능**

---

## 3. **MissionComputer 클래스**

* 문제 2, 3, 4의 핵심 클래스.
* 주요 기능:

  1. **센서 데이터 처리 (`get_sensor_data`)**

     * 5초마다 센서 측정
     * JSON 형태로 출력
     * `sensor_history` 리스트에 기록
     * 60회(=5분) 누적 시 평균값 계산 후 출력
  2. **시스템 정보 출력 (`get_mission_computer_info`)**

     * 20초마다 실행
     * OS, CPU, 메모리 등의 정적 정보 출력
     * 출력 항목은 `setting.txt`로 조정 가능
  3. **시스템 부하 출력 (`get_mission_computer_load`)**

     * 20초마다 실행
     * CPU 사용률, 메모리 사용률 출력
     * 역시 `setting.txt`에서 항목 on/off 가능

---

## 4. **멀티스레드 실행 (run\_threads)**

* 하나의 `MissionComputer` 인스턴스를 공유.
* 그 안에서 3개의 스레드를 병렬 실행:

  * `get_sensor_data`
  * `get_mission_computer_info`
  * `get_mission_computer_load`
* 장점: 메모리 공유 (같은 `MissionComputer` 인스턴스 사용).
* 단점: Python GIL(Global Interpreter Lock) 때문에 **CPU 부하 작업에서는 병렬성이 제한됨.**

---

## 5. **멀티프로세스 실행 (run\_processes)**

* 각각 별도의 `MissionComputer` 인스턴스를 생성.
* 각 프로세스가 독립 실행:

  * 하나는 센서 담당
  * 하나는 시스템 정보 담당
  * 하나는 부하 담당
* 장점: GIL 제약 없음, 병렬성 확보.
* 단점: 메모리 공유가 안 돼서 프로세스 간 상태 공유 어려움.

  * 여기서는 \*\*공유 이벤트(`multiprocessing.Event`)\*\*만 공유해서 종료 시그널만 동기화.

---

## 6. **종료 처리 (wait\_for\_exit)**

* `input()`을 통해 `q` 입력 대기.
* 사용자가 `q`를 입력하면 `stop_event.set()`.
* 모든 루프(`while not stop_event.is_set()`)가 종료됨.
* `responsive_sleep()` 때문에 sleep 중에도 즉시 종료.

---

지금 코드에서 `stop_event = multiprocessing.Event()` 부분이 핵심이에요.
하나씩 풀어서 설명해드릴게요.

---

## 1. `multiprocessing.Event()`의 의미

* **스레드(thread)**

  * **같은 프로세스 메모리를 공유**
  * 글로벌 변수나 mutable 객체(list, dict 등)를 매개변수로 전달해도 **참조 공유** 가능
  * 따라서 스레드끼리 실시간으로 상태를 확인하거나 변경 가능

* **프로세스(process)**

  * **각자 독립된 메모리 공간**
  * 매개변수로 값을 전달하면 **카피(copy)** 되어 들어감 → 원본과 실시간으로 연결되지 않음
  * 따라서 **실시간 상태 공유를 위해서는 `multiprocessing.Event`, `Value`, `Array`, `Manager` 같은 공유 객체**가 필요

---

즉, 핵심은:

> 스레드는 “참조를 공유”할 수 있고,
> 프로세스는 “복사본만 전달”되므로 **공유 객체**를 써야 상태를 실시간으로 참조할 수 있다.

---

원하시면 제가 **스레드 vs 프로세스에서 mutable 객체 전달 차이**를 간단한 코드 예제로 보여드릴 수도 있어요.
그거 보면 감이 확 잡힙니다.

* `multiprocessing.Event()`는 **프로세스/스레드 간에 공유할 수 있는 동기화 객체**예요.
* \*\*기본값은 "unset" (False 상태)\*\*입니다.
  즉, `stop_event = multiprocessing.Event()` 라고만 해도 **초기 상태는 꺼져 있음**이에요.
* 그래서 매개변수를 따로 안 넣어도 되는 이유는:

  * 이벤트 객체는 기본적으로 생성 시 꺼진 상태 (`clear()`)로 만들어지기 때문이에요.
  * 나중에 멈추고 싶을 때 `stop_event.set()`을 호출하면 True 상태가 돼요.
  * 다시 초기화하려면 `stop_event.clear()` 하면 돼요.

즉,

```python
stop_event = multiprocessing.Event()  # 초기 상태 False
stop_event.is_set()  # False 반환
stop_event.set()     # 상태 True로 바꿈
stop_event.is_set()  # True 반환
stop_event.clear()   # 다시 False로 초기화
```

이런 식으로 작동합니다.

## 2. 모든 프로세스와 스레드를 한 번에 멈추는 알고리즘

이 코드의 설계는 **공통된 종료 신호를 이벤트 하나로 관리**하는 구조예요.

### (1) 실행 단계

* 메인 프로세스에서 `stop_event = multiprocessing.Event()` 생성
* 이 이벤트는 **스레드/프로세스에 모두 전달**돼요:

  * 스레드: `run_threads(stop_event)` 호출
  * 프로세스: `run_processes(stop_event)` 호출

즉, **모든 작업자가 같은 이벤트를 바라보게 됨**.

---

### (2) 각 루프에서의 동작

모든 루프(`get_sensor_data`, `get_mission_computer_info`, `get_mission_computer_load`)는 공통적으로 이런 조건문을 가짐:

```python
while not stop_event.is_set():
    ...
```

* 이벤트가 `False`면 계속 실행.
* 이벤트가 `True`가 되면 즉시 루프 종료.

---

### (3) 종료 입력 처리

사용자가 `q`를 입력하면 `wait_for_exit()`에서:

```python
stop_event.set()
```

이 호출됨 → 이벤트 상태가 `True`로 바뀜.

---

### (4) 즉시 멈추는 흐름

1. 모든 스레드와 프로세스는 루프 안에서 **주기적으로 `stop_event.is_set()` 검사**.
2. 검사 시 True가 되면 바로 break → 함수 종료.
3. `responsive_sleep()`도 0.5초 단위로 검사 → sleep 중에도 빠르게 멈출 수 있음.
4. 따라서:

   * 센서 데이터 수집 스레드
   * 시스템 정보 스레드
   * 시스템 부하 스레드
   * 센서 데이터 프로세스
   * 시스템 정보 프로세스
   * 시스템 부하 프로세스
     이 6개가 동시에 멈춤.
5. 마지막으로 메인 프로세스에서:

   * 프로세스들은 `terminate()` + `join()`으로 안전하게 종료 처리.
   * 스레드들은 `join()`으로 정리.

## 3. 그림으로 표현하면

```
                [Main Process]
                      |
          ------------------------------
          |                            |
   [Threads Runner]               [Processes]
   |      |      |                 |     |     |
 Sensor  Info   Load            Sensor Info  Load
   \      |      /                 \     |     /
     -----+--------------------------+---------
                stop_event 공유
```

* `stop_event.set()` 되면,
  모든 프로세스/스레드 루프 조건이 깨져서 종료됨.

---

✅ 요약:

* `multiprocessing.Event()`는 기본값이 False라서 매개변수 없이 생성해도 됨.
* `stop_event` 하나를 모든 프로세스/스레드가 공유하고 `is_set()` 검사함.
* `q` 입력 → `stop_event.set()` 호출 → 모든 루프가 동시에 빠져나옴.
* 따라서 **"즉시 멈춤"이 전체 동작에 전파되는 알고리즘**임.

## 7. **메인 실행부**

1. 실행 시작 → 작업 경로를 현재 파일 위치로 고정 (`log`가 같은 경로에 저장됨).
2. `stop_event = multiprocessing.Event()` 생성 (프로세스/스레드 간 공유 가능).
3. 멀티프로세스 실행 시작.
4. 멀티스레드 실행 시작.
5. `wait_for_exit()`로 종료 대기.
6. `q` 입력 시:

   * `stop_event.set()` 호출.
   * 모든 쓰레드 루프 종료.
   * 프로세스는 `terminate()`로 강제 종료 후 `join()`.
7. 최종적으로 `"== 모든 스레드 및 프로세스 종료 완료 =="` 출력.
